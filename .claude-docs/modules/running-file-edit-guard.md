# running-file-edit-guard — правка файла, который исполняется прямо сейчас

**Файл:** `hooks/running-file-edit-guard.sh`
**Событие:** PreToolUse на `Write|Edit|MultiEdit`
**Свидетель:** `hooks/tests/test_running_file_edit_guard.sh` — 11 проверок, включая
отрицательный класс признака и одноимённый другой файл

## Зачем

Оболочка дочитывает скрипт с диска ЛЕНИВО, по мере исполнения. Правка сдвигает байтовые
смещения, и указатель чтения попадает в середину слова — бегущий прогон умирает
синтаксической ошибкой там, где кода никто не менял.

Класс проявился дважды за одну сессию 23 сентября 2026: прибор ложной зелени
(`scripts/behavior-condition-probe.sh`) умер на середине, и набор
(`hooks/tests/run_all.sh`) — на 400 тестах из 555, с сообщениями «мауту: command not found»
и «syntax error near unexpected token `done`». Оба раза вход решения «править сейчас» был
ПУСТ: факта «файл занят исполнением» не добывал никто.

Чем решалось раньше: ничем. На `Write|Edit|MultiEdit` стоят `secret-guard`, `budget-gate`,
`lib-prefix-guard`, `test-exit-explicit-guard` — ни один не спрашивает про занятость файла.

## Договор

Вход — payload PreToolUse. Судится только `*.sh`: интерпретатор Python читает файл целиком,
и класс его не задевает. Страж разбирает командную строку живых процессов ПО СЛОВАМ и ищет
ИСПОЛНЕНИЕ (`bash <файл>` либо файл как argv[0]), а не упоминание — процесс, который лишь
читает файл (grep, редактор, git), правке не мешает.

Исполняемое слово судится ИДЕНТИЧНОСТЬЮ файла, а не именем (D1090): абсолютное — `-ef` с правимым (устройство и
inode, ссылки раскрываются), относительное — от каталога процесса (Linux — `/proc/<pid>/cwd`, macOS — `lsof`).
Установленная копия хука (`~/.claude/hooks/<имя>.sh`), исполняющаяся на ту же правку, — другой файл, и правка копии в
репозитории тревоги не даёт. Путь, не разворачивающийся в существующий файл (процесс сменил каталог, как `run_all.sh`;
каталога не узнать; путь с пробелом разрезан на слова), судится прежней сверкой по имени: пропуск занятого файла дороже
ложной тревоги.

Выход — `additionalContext` с числом процессов и их идентификаторами. Код всегда 0.

## Уровень

Подсказка, не отказ. Точность измерена на ДВУХ случаях одной сессии; ложные срабатывания на
корпусе не измерены — следа «файл был занят в момент правки» система не пишет. Один класс ложных измерен и снят:
одноимённая установленная копия — 7 из 7 срабатываний одного хода правки `hooks/impact-inject.sh` (D1090).

Условие снятия: появится выборка правок занятых файлов с записанными исходами — тогда
точность станет измеримой, и признак с одним последствием можно перевести в отказ.

## Названный предел

Судится состояние на момент вызова. Прогон, запущенный между проверкой и записью, страж не
увидит — гонку он не закрывает.

Условие снятия: появится способ держать файл под замком на время правки (тот же протокол,
что у `hooks/state-lock-lib.sh`), и тогда гонка закроется замком, а не наблюдением.
