# Модуль: guard-event-coverage (страж видит оба пути правки)

**Назначение.** Страж, объявивший предметом ПРАВКУ файла, обязан видеть оба пути, которыми
правка приходит: инструмент (`Edit`/`Write`/`MultiEdit`) и команду (`Bash` — heredoc,
`sed -i`, перенаправление). Прибор читает регистрацию из `install.sh` и называет слепых.

**Файлы.**
| Файл | Роль |
|---|---|
| `scripts/guard-event-coverage.sh` | замер и вердикт: код 1, пока есть слепые |
| `hooks/tests/test_guard_event_coverage.sh` | свидетель, 7 ног: слепой назван поимённо, видящий Bash чист, молчащая шапка не судится, исключение снимает вердикт, чужой проект — тишина, знаменатель назван числом |

**Зависимости.** python3 (stdlib), git; состав регистрации — `install.sh` (владелец по ADR-009).

**Повод и замер (13 сентября 2026, D407).** За сессию правлено 11 файлов кода, через хук
карты связей прошло НОЛЬ: он висел на `Edit|Write|MultiEdit`, а правки шли командой Bash.
У `backlog-open-write-guard` — отказа УРОВНЯ 4 — срабатываний 0 при четырёх коммитах,
тронувших BACKLOG.md. Судимых стражей 28, слепых 9, трое из них отказывают.
Знание об этом классе лежит с 27 августа (`case-2026-08-27-tool-name-detection-blind-to-work-mode`:
правок оболочкой 1357 против 1675 файловыми, 45%) и ни одним стражем применено не было.

**Покрытие бывает не только своей регистрацией.** Страж, чью правку подаёт диспетчер
`hooks/bash-write-dispatch.sh`, слепым не считается, хотя его подписка не менялась. Список
берётся У ВЛАДЕЛЬЦА — строка `GUARDS=` диспетчера, — а не переписывается здесь: копия
правила у потребителя есть род K. Показание на 13 сентября 2026: судимых 29, покрыто
диспетчером 3, слепых 5.

**Признак судит УСТРОЙСТВО, а не прозу шапки** (13 сентября 2026). Отбор по словам
«правка/запись/файл» в шапке дал девять стражей; из них путь или тело файла читают ВОСЕМЬ.
Девятый — `budget-gate.sh`: из входа он берёт только `session_id` и `tool_name` (`:39-40`),
и его вывод побайтово одинаков на чистом и на нарушающем файле, то есть предмет у него
иной. Поэтому к признаку добавлено условие «читает предмет из входа»: судимых 29 → 15,
слепых 5 → 4.

**Правила.**
- Предмет опознаётся по ШАПКЕ стража (первые четыре строки: «правка», «запись», «файл») —
  признак судит ОБЪЯВЛЕНИЕ. Названный предел: страж, чья шапка молчит о предмете, не судится
  вовсе. Условие снятия — у хука появится объявленное поле предмета, а не проза шапки.
- Исключение пишется В САМОМ СТРАЖЕ: `bash-путь: не нужен — <почему>`. Умолчание неотличимо
  от «не посмотрел», поэтому молчаливых исключений нет.
- Число слепых держит замер `guard-event-coverage` (период 30 коммитов), а не память.
