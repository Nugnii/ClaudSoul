# project-map — описание устройства проекта для учёта и карты связей

**Назначение.** Один владелец ответа «что в ЭТОМ проекте код, тест, что не смотреть, что такое файл-договор, какие
переменные значат корень и куда класть карту связей». Описание живёт в самом проекте —
`<корень>/.claude-docs/project-map.json` — и растёт с ним (слово владельца 24 октября 2026: «у каждого проекта свой
бэклог и свои связи… в проект имплементируется принцип и там развивается»). Без описания действуют умолчания.
У ClaudSoul описание своё: в нём названы его переменные корня и договоры. Спецификация —
`.claude-docs/specs/2026-10-24-project-map-principle/spec.md` (локальная, шаги 1б.1–1г); пункты долга — D1067, D1079,
D1089.

**Файлы.** `hooks/lib/project_map.py` (модуль; самопроверка — `python3 hooks/lib/project_map.py <корень>`),
`.claude-docs/project-map.json` (описание ClaudSoul), свидетель `hooks/tests/test_project_map.sh`. Потребители:
`scripts/dep-index.py` (владелец рёбер учёта) и `scripts/project-graph.py` (карта) — оба зовут модуль вместо прежних
копий правил (MECH_RE/MECH_SKIP/TEST_RE, `_MECH_SKIP`/`_is_mech`/`_TEST_RE`). `git(repo, *args)` — git в судимом дереве
для обоих приборов: зовёт `project_git` из `hooks/paths-lib.sh` (лежит уровнем выше модуля; нет её или функции —
отказ `DescriptorError`, голого git нет).

**Описание (поля).** `version` (только 1); `code` — непустой список `{glob, lang}`; `tests` — образцы тестов;
`ignore` — что не смотреть; `repo_vars` — голые имена переменных, чьё значение — корень этого проекта (`REPO`, а не
`$REPO`); `contracts` — образцы файлов-договоров (данные, которые код читает и пишет); `roots` — список
`{dir, tsconfig}`: корень TS/JS и его конфиг с псевдонимами импортов. Языки: `shell`, `python`, `tsjs`, `swift`. Путь карты
описание не выбирает (D1070). Образцы — по компонентам пути: `**` — ноль и более каталогов, хвостовой `**` — один и более
(`tests/**` не совпадает с файлом `tests`), прочее — `fnmatchcase` одного имени (`*`/`?` не пересекают `/`), скобки
буквально.
Умолчания: код `**/*.sh` (shell), `**/*.py` (python); тесты `**/test/**`, `**/tests/**`; не смотреть `templates/**`,
`scripts/publish/**`, `**/*__init__.py`; переменные корня `REPO`, `ROOT`; договоры `BACKLOG.md`, `ROOTS.md`, `**/*.tsv`,
`**/*.json`, `**/*.yml`, `**/*.yaml`, `**/*.toml`; карта — `mcp-server/visualization/project-graph-data.json`, если
каталог дашборда есть, иначе `.claude-docs/project-graph.json`.

**Рёбра по импорту (шаг 1в, D1079).** `import_refs(m, repo, path, code, universe)` — единственное правило «импорт →
файл дерева» для учёта (`deps` — к механизмам; `tests` — тест, импортирующий или подменяющий файл, его тест, решение
владельца 25 октября 2026) и карты (`body_deps`, роль «зовёт»). Вселенная — файлы языков кода, тесты включая. Ребро
даёт только импорт, РАЗРЕШЁННЫЙ в файл дерева: TS/JS — `import … from`, `export … from`, `import '…'`, `require('…')`,
`import('…')` с литералом, `vi.mock`/`jest.mock`; относительный путь и псевдоним из `tsconfig` корня (`paths`,
`baseUrl`, относительные `extends`), подбор расширения и `index.*`. Python — `import a.b`, `from a.b import c` (и
подмодуль), относительные `from .m import n`; каталог скрипта первым в пути поиска, затем корень, затем единственный в
дереве модуль с таким именем вне стандартной библиотеки. Пакеты, `import(переменная)`, закомментированный импорт
рёбер не дают. Правка `tsconfig` корня — вход каждой строки (полная сборка сравнением). Пределы: шаблонная строка в
`import()`, `extends` пакетом, `python -m` с иным путём поиска.
Swift (7 ноября 2026) импортом файла не называет: ребро A→B — имя верхнего уровня B (тип, `typealias`, функция,
глобальная `let`/`var`), названное в коде A без комментариев и строк; слово после одиночной `.` — член чужого значения
(`menu.delegate`) и ребра не даёт, кроме полного имени `Модуль.Тип` (D1264); имя, объявленное в двух файлах, ребра не даёт;
имя чужого модуля (каталог под `Sources/` или `Tests/`) — только при `import` этого модуля; `private`/`fileprivate`
верхнего уровня видны только своему файлу и в перечень не входят. Текст Swift разбор читает с диска сам: вызывающий
снимает строки, начатые `#`, а в Swift это код (`#expect`, `#if`). Ребро зависит от СОДЕРЖИМОГО цели, поэтому правка
Swift-файла делает неверными чужие строки: `invalidated_by` называет Swift-строки, не равные собранным заново (`_row`
учёта), а `touch` карты пересчитывает рёбра всех Swift-узлов. Без сборки и без новых
зависимостей (выбор владельца). Потолок: члены и вложенные типы не судятся, доступ (`internal`) не судится, имя в
интерполяции строки снимается, локальное имя, совпавшее с глобальным, даёт ложное ребро; переход — индекс компилятора.
Проза питона (D1286) — `py_prose_rows(text)`: строки литерала в тройных кавычках, чей токен открывает свою строку
(докстринг, строка-выражение), по `tokenize`, f-строки 3.12 тоже; None — разбор не удался. Один разбор для карты
(`code_lines`) и учёта (`code_only`): прежний счёт кавычек читал строку, начатую закрывающей `'''`, как начало
докстринга и выбрасывал остаток файла. Многострочный литерал в выражении (`X = '''…`, аргумент) — код, как было.

**Рёбра к договорам (шаг 1б.2).** `contract_refs(m, text, contracts)` — единственное правило «литерал кода → путь
договора» для учёта (колонка `deps`) и карты (`body_deps`, роль ребра), поэтому инкремент `--touch` равен сборке по
построению. Литерал даёт ребро, только когда РАЗРЕШАЕТСЯ в путь отслеживаемого договора: путь от корня с левой
границей (начало, пробел, кавычка, `=`, `(`, обратная кавычка) — лишь у пути с `/`; путь после переменной корня
(`$V/…`, `${V}/…`, `${V:-…}/…`, `"$V"/…`, в Python `V / "…"`, `join(V, "…")`, `{V}/…`, а также по звеньям —
`join(V, "a", "b.tsv")`, `V / "a" / "b.tsv"`); путь объекта git
`<ревизия>:<путь>`. Правая граница исключает `foo.md.bak`, `BACKLOG.md-old`. Голое имя ребра не даёт никогда (у файла
в корне путь равен имени — F1 D1067), путь после чужой переменной тоже (`$dir/CLAUDE.md`, `$HOME/.claude/…` — F1/F3).
Договор — подходит `contracts`, не код и не тестовый код, не «не смотреть», не кэш карты (`is_contract`); данные в
каталоге тестов (реестры `hooks/tests/*.tsv`) — договоры; учёт — договор,
который прибор сам пишет, и его путь входит во вселенную до первой записи.
Роль ребра решает карта (`contract_kind` → `dep_role`): запись (переадресация, `tee`, `sed -i`, последний аргумент
`mv`/`cp`/`install` — в том числе после `;`, `&&`, `||`, `(`, `then`/`else`/`do`, второй аргумент `os.replace`/
`shutil.copy*`/`shutil.move`, `open(…, 'w')`, `.open('w')`, `.write_text`) — «записывает»; источник `cp`/`mv` с флагом
и без — чтение; все строки — сообщение, проза в кавычках (пробелы после свёртки `${…}`), обратные кавычки, образец
`case`, сравнение (`=` — только у оболочки), исключение, ключ словаря — «называет»; иначе «читает». Путь, присвоенный
переменной (`N="$REPO/…"`, `N="${E:-$REPO/…}"`, `${N:=…}`, после `(`/`)` ветки `case`/`{`, `local`/`export`/`readonly`,
в Python `N = …`, в том числе внутри `abspath(`/`str(`, кроме строки-продолжения вызова), судится местами, где
переменная используется целиком (`$N`, `${N}`, `${N:-…}`, `${N:?}`; `${N%/*}`, `"$N.lock"`, `N + ".lock"` — уже
другой путь), — один шаг. «Зовёт» договору не ставится никогда. Читателей, чей путь правило не разрешает, карточка
называет оговоркой (`unresolved_namers` в `scripts/project-graph.py`): механизмы, чьи строки кода называют имя
договора целым словом, а ребра нет, — «имя называют ещё N без пути, который разрешает карта (связь не проверена)»;
ребром они не становятся, потому что одноимённый файл другого проекта правило от такого читателя не отличит. Договор, которого в дереве уже нет, узла в карте не рождает, даже при отставшей строке учёта.

**Свежесть учёта (шаг 1б.3).** `invalidated_by(changed, rows)` в `scripts/dep-index.py` — владелец ответа «какие
строки сдвинула правка помимо самих механизмов»: изменилось описание — все строки; договор появился или удалён —
строки его читателей (прежних по `deps` и новых по коду), и только те, чьи рёбра действительно сдвинулись; изменился
тест или документ — строки, у которых сдвигается колонка `tests` либо `docs` (коммит одних тестов тоже пересобирает
учёт); к какому корпусу файл относится, решают те же `tests()` и `documents()`, что у сборки (README в каталоге
тестов — документ, реестр там же — ни то ни другое); удалён механизм — строки, чей `deps` его называет; появился —
перечень называет его самого, и сборка идёт целиком; сменился СОСТАВ группы одноимённых механизмов (не только
набор неоднозначных имён: из трёх двойников удалён один) — все строки; изменён код самого правила, когда он лежит в
судимом дереве (`rule_files()`: `scripts/dep-index.py` и модуль описания), — все строки; правка содержимого договора
пересборки не требует. Редакцию правила помнит и сам учёт: строка шапки `# правило <хеш>` — хеш кода прибора и
модуля описания, где бы они ни лежали (`rule_stamp`); отметка не совпала с нынешней либо её нет — все строки, и
отчёт `--impact` по такому учёту новых публичных имён не называет, а говорит «учёт собран другой редакцией правила»
(так смену правила видит и чужой проект, чей учёт строит прибор вне его дерева). Его зовёт `--changed`. Ответ «какие строки правка сделала НЕВЕРНЫМИ» — у `stale_rows`: механизм с иным
содержимым (в том числе правленный внутри области данных), новый без строки, удалённый при живой строке, плюс
`invalidated_by`; уже пересобранная строка туда не попадает, а где сдвиг — «все строки», ответ даёт полная сборка
сравнением с записанным (на ClaudSoul около 1 с, на ProjectA_NEW 18 с; отчёт `--impact` называет правку кода правила и описания своей строкой без
полной сборки). Его берут `--impact` (строки учёта устарели) и режим `--stale-by <пути>`: пусто — учёт свеж, и
хук коммита `doc-impact-check` по этому ответу решает, пересобирать ли. Ответ — о том дереве, которое прибор судит:
хук коммита зовёт его в выгрузке индекса коммита, поэтому файлы рабочей копии вне коммита на ответ не влияют. Хук отдаёт пути без распознавания
переименований (оба пути) и называет индексатору своё дерево (`CLAUDSOUL_REPO="$ROOT"`).

**Любой проект (шаг 1г, D1089).** Подсказка перед правкой (`hooks/impact-inject.sh`) и хук коммита
(`hooks/doc-impact-check.sh`) в рабочей копии ClaudSoul зовут его приборы, как прежде; в любом другом проекте с
описанием — приборы ClaudSoul (`CLAUDSOUL_ROOT`) против корня проекта (`--repo` у карты, `CLAUDSOUL_REPO` у учёта),
без описания — молчат. Код проекта не исполняется: одноимённые `scripts/*.py` проекта не зовутся, реестр родов
(`scripts/defect-class-carriers.py`) карта зовёт только у своего дерева (`_own_tree`), git приборов идёт через
`project_map.git`, git хука коммита — через `project_git`, diff с содержимым — с `--no-ext-diff --no-textconv`
(внешний diff и textconv настройкой не гасятся). Карточка `--node <путь> --brief` отвечает тремя ответами: «на нём
стоят N: …», «на нём не стоит никто» (у договора — с оговоркой о читателях без разрешённого пути, если
такие есть) и — для файла дерева, у вида которого нет правила входящих рёбер (`kind_known`:
не код, не тест, не договор), — «карта этого вида не знает — допиши .claude-docs/project-map.json» с кодом 5.
Подсказка отбирает файлы по ответу прибора, а не по расширению; строки про `run_all.sh --changed` и пересчёт чисел
документов звучат только в ClaudSoul, команды в сообщениях названы с путём прибора и `--repo`.
Предфильтр упоминаний: `mentions` зовёт выражение только у файлов корпуса, где основа имени стоит целым словом
`[A-Za-z0-9_-]+` (все три формы совпадения этого требуют), — учёт побайтно тот же, полная сборка ProjectA_NEW 518 с →
18 с, ClaudSoul 16 с → 1 с.

**Заведение и сверка (шаг 1д, D1096).** `project_map.propose(repo)` (CLI `python3 hooks/lib/project_map.py --propose
<repo>`) предлагает описание по дереву: `code` — языки по расширениям отслеживаемых файлов (shell/python/swift, у swift ещё
тесты `**/Tests/**`; tsjs под каталогами с `tsconfig.json`), `roots` — корни TS с их конфигом. Предложение — стартовая точка, владелец правит руками.
`/init-project` (скилл, раздел 6b) для git-репозитория без карты пишет описание, собирает учёт (`dep-index.py --repo
--all`) и карту (`project-graph.py --repo --refresh`) и кладёт карту в `.gitignore` (описание и учёт — под git, карта
пересобирается — решение владельца). `scripts/project-conformance.sh` (секция 7): нет `.claude-docs/project-map.json` —
расхождение «карты связей нет»; есть — свежесть учёта (`dep-index.py --repo --check`) и справкой число файлов языка вне
`code` («виды, которых описание не знает»). git приборов — через `project_map.git`; инструменты ClaudSoul, не код проекта.

**Правила.**
- `--repo <путь>` у учёта и карты — корень чужого проекта; прежние вызовы его не передают и получают прежний корень
  (учёт — каталог своего скрипта либо `CLAUDSOUL_REPO`, карта — корень git каталога вызова либо `CLAUDSOUL_REPO`).
- Описание есть, но не прочитано или не разобрано — отказ с кодом 2 и именем файла: «не прочитал» не вправе молча
  стать «описания нет» и подменить устройство проекта умолчаниями (род B).
- Модуль ищется порядком `hooks/paths-lib.sh:33`: рядом со скриптом, `CLAUDSOUL_ROOT`, указатель
  `~/.claude/claudsoul-repo`, установка. Не найден — запасной путь с прежними правилами дословно и без договоров
  (песочницы тестов копируют только инструмент и подменяют HOME, на CI нет ни указателя, ни установки); громко там,
  где без модуля честно не исполнить: описание лежит на месте либо передан `--repo`. Совпадение путей держит нога P6.

**Договор входа (D1068, D1070, D1071).** Описание чужого репозитория — граница доверия. Неизвестное поле, поле не
того типа, неизвестный язык (`shell`, `python`, `tsjs`, `swift`), пустой `code`, `version` не целое 1, `repo_vars` не голыми
именами — отказ с кодом 2 и причиной; путь записи описание не выбирает. Учёт и карта не пишут, если каталог записи
после раскрытия ссылок вне проекта, на пути висячая ссылка, файл записи или его замок `<файл>.lock` — ссылка
(`safe_output`); временный файл учёта создаётся с `O_EXCL|O_NOFOLLOW`. `--repo X` и `--repo=X` — существующий корень
git-дерева (проверка по раскрытому пути, наружу отдаётся путь как дан); повтор, пустота, каталог без git, подкаталог —
отказ 2. Ноль файлов кода по описанию назван причиной (язык вне разбора либо образцы не нашли файлов). Любой путь
учёт, карта (`touch`, `--node`) и хук `impact-inject.sh` переводят в путь от корня одним владельцем `rel_path`: имя,
которое владелец ключей уже знает (у учёта — строки учёта и файлы git, у карты — её узлы), идёт как есть, поэтому
NFC-имя git при NFD на диске и путь файла, удалённого коммитом, остаются своими ключами — в любой форме входа: знакомое
сверяется текстом (`text_rel`: `./` и корень снимаются — как дан, после `realpath` или через иной псевдоним вроде
`/var` ↔ `/private/var`, его судит `stat` префикса; звено `..` решает файловая система только до последнего `..`, хвост
остаётся текстом; каталог на диске обязан лежать в дереве, иначе это не тот файл) и после раскрытия каталогов. Хук
подсказки переводит цели тем же владельцем с ключами карты — подпись карточки, флаг дедупа и `ls-files` получают ключ
карты, а не набранный текст; библиотека, которая не грузится, — прежняя склейка `normpath`. Незнакомое — относительное от
корня из любого каталога; каталог раскрывается с обеих сторон, имя файла — нет, поэтому реальная и ссылочная формы
дают один ключ; `..` после ссылки решает файловая система; имена звеньев берутся с диска (`listdir` — раз на каталог),
и на нечувствительной к регистру системе `X/a.sh` и `.GIT` — те же `x/a.sh` и `.git`. Выход за дерево судит
`outside()`; `x/` и `x/.` — каталог. Выходы инструментов (учёт, кэш карты, замок) не носители в учёте; кэш карты и
замок в любом регистре — не узлы карты (учёт остаётся узлом-реестром). Карта строится в проекте без
`.claude-docs/` и без учёта; свежесть кэша судится по учёту, без учёта — по индексу git. `--touch` вносит и файл,

**Названные пределы.** Путь, собранный по частям (`join(V, "scripts", "x.tsv")`, `"$D/$N.tsv"`), и путь через
переменную, не названную в `repo_vars`, ребра не дают; запись через переменную на другой строке видна как чтение;
проза внутри многострочной строки (кавычка открыта строкой выше) видна как чтение — на 25 октября 2026 одно ребро из
51 (`knowledge-frontmatter-check.sh` → `knowledge/META.md`). Правка описания проекта в коммите пересобирает все
строки (около 1 с на ClaudSoul, 18 с на ProjectA_NEW), даже если учёт уже собран по новому описанию. Переменная с путём, переданная программе
(`python3 - "$N"` и `sys.argv`, `env N=… python3 -` и `os.environ`, функция, `export` дочернему процессу), видна как
чтение — решение владельца 30 октября 2026 (на дереве три ребра); шаг по переменной один и без порядка
(одноимённая переменная другой функции — та же). Проверка записи (`safe_output`) идёт до записи: ссылка, подложенная между проверкой и записью,
ведёт наружу (локальная гонка; замок — `os.mkdir`, кэш карты — `open(…, 'w')`). Запасной путь — вторая запись правил
умолчания; держит его нога P6, а не текст. Пределы перевода пути (D1073): `--changed` с одним прежним именем файла,
переименованного по регистру, пересчитывает только прежнюю строку — новую называет `--check` (громко; хук коммита
подаёт оба имени из git); git с `core.precomposeunicode=false` ключует NFD-именами, и NFC-вход их не находит (на macOS
по умолчанию `true`); на чувствительной к регистру системе файл `Project-Graph.JSON` рядом с кэшем карты отказывается
как кэш.
