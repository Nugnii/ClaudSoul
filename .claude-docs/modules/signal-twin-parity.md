# signal-twin-parity — признак видит запись в код, чем бы она ни была сделана

**Назначение.** Подаёт признаку настоящую запись файла через `python3 - <<EOF` с `open(path,"w")` и смотрит, опознан ли дефект. Чистая запись обязана остаться без срабатывания.

**Файлы.** `scripts/signal-twin-parity.sh`, свидетель `hooks/tests/test_signal_twin_parity.sh` (7 ног). Потребитель — строка «Проверка» пункта D415.

**Зависимости.** `hooks/detection-signals-lib.sh` — ВЛАДЕЛЕЦ разбора признаков; своей копии разбора здесь нет. `python3`, `jq`.

**Правила.**
- **Судится ПОВЕДЕНИЕ, а не текст.** Счёт форм по тексту знания эту дыру не ловит: при заведении пункта D415 правка руками сломала JSON признаков кавычкой внутри строки — блокер знания замолк целиком, а счёт по `awk` остался зелёным. Поэтому отдельной веткой стоит предикат «разбор состоялся», дающий отказ (код 2), а не ноль.
- **Образец собирается из частей.** Записать дефект литералом в файл под `scripts/` нельзя: живой блокер отказывает такой записи — проверено на себе в час заведения.

**Названный предел.** Судится ОДИН способ записи — питон внутри heredoc, самый частый: 57 из 77 команд окна. Прочие невидимые способы (`tee`, `ed`, `printf` в цикле) прибором не покрыты. Условие снятия: замер назовёт второй способ числом — его образец добавляется сюда же.

**Повод (D415).** Признак узнаёт запись в файл по ЦЕЛИ heredoc. У записи питоном цель — стандартный вход питона, путь лежит в ТЕЛЕ, и предикат цели не совпадает по построению: видно 20 записей из 77, невидимо 57.
