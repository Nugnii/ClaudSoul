# Модуль: внешний замер исхода (usage-outcome-audit)

**Назначение.** Единственный замер реестра, который смотрит на результат работы, а не на исправность машинерии. Читает отчёт Claude Code Insights (`~/.claude/usage-data/`) — разметку сессий сторонней моделью, не знающей про ClaudSoul: типы трения, исходы, сигналы удовлетворённости. Даёт протоколу ablation метрику исхода, которой у него не было, и проверку на вменяемость внутренних метрик.

**Файлы.** `scripts/usage-outcome-audit.py`; строка `usage-outcome` (период 0 — по событию, снимок разовый, D71) в `scripts/measurements.tsv`.

**Зависимости.** Каталоги `facets/` и `session-meta/` внутри `USAGE_DATA_DIR` (умолчание `~/.claude/usage-data`). Данные не обновляются сами — их пересобирает отчёт Claude Code Insights; способ запуска отчёта в CLI не найден, все файлы датируются одним прогоном.

**Правила.** Покрытие печатается ДО любых выводов и двумя окнами раздельно: сам отчёт склеивает окно всех сессий с окном разметки и даёт картину впятеро мягче реальной (pattern-subject-of-measurement-mismatch). Трения делятся на вход (не понял рамку), выход (сказал «готово» без проверки) и среду; перекос называется только при двукратной разнице и ≥3 сессиях. Разбивка по неделям печатается, но кодом возврата не судится — точек слишком мало. Коды: 0 чисто, 1 находка (данные старше `USAGE_MAX_AGE_DAYS`=14 либо покрытие ниже `USAGE_MIN_COVERAGE`=0.5), 2 не смог отработать. Тест: test_usage_outcome_audit (9 проверок).
