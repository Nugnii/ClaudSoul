# docs-derived — производная языковая версия и её отставание от источника

**Назначение.** В работе живёт одна языковая версия документа — русская; английская есть
ПРОИЗВОДНАЯ: она не правится по ходу, а пересобирается переводом перед публикацией. Модуль
делает отставание производной версии наблюдаемым и непропускаемым: записывает его в самом
файле хешем источника, даёт сверщикам в работе пропускать отставшее с названным числом, а
публикации — отказывать на отставшем поимённо.

**Файлы.** `hooks/docs-derived-lib.sh` — единственное определение признака и состояний
(префикс `docs_derived_`); `scripts/docs-derived-check.sh` — прибор: сверка, перечень,
`stamp` (записать хеш после пересборки); тест `hooks/tests/test_docs_derived.sh` (15 ног,
включая положительный контроль «чужой хеш в шапке — отставание» и «без библиотеки — 2, а не
молчаливый 0»); нога T12 в `hooks/tests/test_publish_public.sh` — отказ публикации на
отставшем и проход на свежем.

**Зависимости.** `git hash-object` (считает без репозитория — тесты в песочнице), `awk`,
`sed`, `hooks/state-lock-lib.sh`. Библиотека мир не меняет, кроме `docs_derived_stamp`;
корень для пути источника — `DOCS_DERIVED_ROOT`, иначе верх git у каталога файла.

**Замок (род H).** `docs_derived_stamp` правит README и справочник — файлы, в которые пишут
и другие механизмы, — и берёт общий замок на том же имени, что соседи (`count-stats.sh`,
`docs-refresh-claims.sh`). Временный файл с `mv` даёт атомарность ОДНОГО писателя; от потери
чужой правки защищает только замок. Библиотеки замка нет — правка идёт без него, и это
сказано вслух: молчание неотличимо от «замок взят». Поймано прибором родов в час написания:
способ записи был взят с ФОРМЫ соседнего кода, а не со списка писателей файла. Тем же корнем
закрыт брат — `docs-refresh-claims.sh` писал те же документы из python без замка, и признак
прибора его не видел, потому что смотрит оболочечную форму.

## Признак и состояния

Производный документ несёт в первых пяти строках `<!-- derived-from: <источник>@<хеш> -->`,
где источник — путь относительно корня репозитория, хеш — первые 12 знаков `git hash-object`
источника. В отрисованном Markdown строка невидима. Состояния (`docs_derived_state`):
`none` — шапки нет, документ не производный; `fresh` — хеш совпал; `stale` — источник ушёл
вперёд; `broken` — шапка есть, источника нет. Коды 0/0/1/2: «отстал» и «сломан» — разными
кодами, три состояния прибора.

## Потребители

- `scripts/publish-public.sh` — предусловие ДО снимка: код 1 или 2 у прибора — отказ с
  выводом прибора и командой `stamp`; прибора нет — предупреждение «НЕ ИЗМЕРЕНО», а не
  молчание (это свой инструмент, отсутствие есть поломка).
- `scripts/docs-refresh-claims.sh`, `scripts/docs-inventory.sh`, `scripts/docs-staleness.sh`
  — в работе ОТСТАВШИЙ производный пропускается и называется числом; свежий сверяется
  наравне со всеми. Перечень берётся у прибора (`stale`), не считается у потребителя.
- **Генераторы чисел переставляют штамп сами — по снимку, взятому ДО правки**
  (`scripts/count-stats.sh`, `scripts/docs-refresh-claims.sh` в режиме записи). Они ведут обе
  языковые версии синхронно, меняя только числа, поэтому производный, свежий до прогона,
  остаётся свежим после: иначе он отставал бы после КАЖДОГО пересчёта, а признак, краснеющий
  на правильной работе, обязан быть сужен. Снимок берётся именно до правки — это и есть
  защита от маскировки: отставший по ПРОЗЕ в снимок не попадает и остаётся отставшим
  (ноги T9-T9c теста; без них автоштамп превратил бы непереведённую правку в «свежо»).
- `hooks/docs-family-check.sh` — производный ЛЮБОГО состояния в семью бампа не входит (он
  не правится при бампе), отставший не судится по автотаблицам. Запасная ветка объявляет
  `docs_derived_state`, чтобы под `set -u` хук не умер без библиотеки.
- Роль CLI владельца: `bash scripts/docs-derived-check.sh stamp <файл>` после пересборки
  перевода — источник берётся из шапки либо `<файл>.ru.md` рядом.

## Чем решалось раньше — и судьба предшественников

`scripts/docs-duplicates.sh` выводит язык перевесом букв и в шапке называет условие снятия
предела: «появится явное объявление языка в самом документе (поле шапки)». Шапка
`derived-from` и есть такое объявление; сверщик дублей ОСТАЁТСЯ и к ней не подключён —
отдельный заход. `scripts/regen-readme-skills.sh` и `scripts/count-stats.sh` пишут в обе
языковые версии генерацией, не переводом — остаются: перевод касается прозы.

## Пределы

Хеш ловит любую правку источника, включая правку одной цифры. Для генераторов чисел это
снято снимком «свежих до правки» (см. потребителей); для всякой ПРОЧЕЙ правки источника —
остаётся по замыслу: правка прозы обязана вести к пересборке перевода. Второй хеш по
нормализованному тексту не заводится: он скрыл бы первую же ошибку нормализации.
Наблюдение 14 сентября 2026, ради которого снимок и появился: первый же прогон
`docs-refresh-claims.sh run` после штамповки трёх пар уронил README.md в «отставшие»,
изменив в источнике только числа (575→580, 552→553, 24 375→24 482) — и те же числа в
производном. Штамп при отсутствии
шапки ставит её первой строкой — документ с YAML-шапкой получил бы комментарий выше неё;
таких среди производных нет, и это не ловится. Штамп на нынешних трёх парах (README,
справочник, входной текст) означает «свежи на 14 сентября 2026» по решению: совпадение
смысла перевода хешем не проверяется, только последующее расхождение.

## Повод

Решение владельца 14 сентября 2026: «в работе вторые языковые версии не участвуют и
пересобираются при публикации в паблик». До этого обе версии правились в связке — 39
коммитов README из 40 тронули оба файла, реестр чисел держал по 59 строк на язык.
