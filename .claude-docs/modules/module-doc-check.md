# Модуль: страж модульной документации (module-doc-check)

**Назначение.** Новый модуль в коммите обязан приходить со своим доком: механизирует правило «новый модуль → документация модуля», которое текстом не исполнилось ни разу (41 хук, ноль доков к моменту заведения конвенции).

**Файлы.** `hooks/module-doc-check.sh` (PreToolUse[Bash] на `git commit`).

**Зависимости.** git (staged diff), jq; каталог `.claude-docs/modules/` трекается (негация в .gitignore — машинные логи рядом остаются игнорируемыми).

**Правила.** Сигнал правилом, не перечнем: новый (статус A) исходник `.sh`/`.py` в любом месте дерева минус `tests/`, `*-lib.sh`, `templates/`, `scripts/publish/` = модуль; формы задаются `MODULE_DOC_PATTERN` / `MODULE_DOC_EXCLUDE`. Правки существующих и тесты не триггерят. Док в том же staged гасит напоминание. Advisory, не блок; throttle на набор модулей за сессию. Тест: test_module_doc_check (обе стороны).
