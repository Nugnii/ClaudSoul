# backlog-vanish-check

**Назначение.** Не дать пункту долга исчезнуть из `BACKLOG.md` бесследно. Закрытие
законно, переезд в `BACKLOG-archive.md` законен; пропажа без следа — нет.

**Файлы.** `hooks/backlog-vanish-check.sh`, опознание пункта — из общей библиотеки
`hooks/backlog-lib.sh` (своя копия признака здесь уже отказала: 28.08.2026 вёрстка
сменилась, и страж сутки видел ноль идентификаторов), тест `hooks/tests/test_backlog_vanish.sh`
(73 проверок, проверен мутацией: прежняя редакция стража краснит три ноги D435, первая редакция его починки — ноги находок скептика), носитель класса — `hooks/tests/test_payload_cwd_root.sh`. В репозитории с ловушкой git (`commit-trap.sh`, D1022) страж судит в ней — «после» берётся из индекса коммита,
«закрыт» — из готового сообщения, — а на PreToolUse молчит. Регистрация: `PreToolUse[Bash]`, рядом с
`module-doc-check` и `changelog-reminder`.

**Как работает.** На `git commit` берёт идентификаторы пунктов (`- ☐ **D42**` и прочие
статусы) из `BACKLOG.md` на HEAD и сверяет со снимком, который унесёт коммит. Идентификатор,
пропавший из файла и не найденный в архиве, называется поимённо. Хук тихий: печатает
`additionalContext`, ничего не блокирует.

Какой снимок унесёт коммит, решается для КАЖДОГО из двух файлов отдельно (D435) — так же, как это
решает сам git. Файл назван в `git add|stage|rm|mv` до коммита либо аргументом коммита — рабочая
копия; `git add -A|--all|.` — рабочая копия (берёт и неотслеживаемое); `git add -u` и
`commit -a|--all` (в том числе слитно: `-am`) — рабочая копия, если файл отслеживается, иначе
индекс; `git commit <пути>` без файла среди них — файл останется как в HEAD; во всех прочих случаях
— индекс (`git show :BACKLOG.md`, `:BACKLOG-archive.md`). «Всё» и «только отслеживаемое» отвечает владелец
разбора — `executable_commit_adds` (`hooks/command-scope-lib.sh`, сверен с исполнением форм настоящим git). Суд рабочей копии остаётся вдобавок:
потеря в копии уйдёт следующим `git add`. У находки «на диске пункт есть, в индексе нет» своё
сообщение — чаще всего это половина переноса, когда в индекс поставлен один файл из пары.
«Это коммит?» спрашивается у владельца (`is_git_commit`), форма читается с исполняемой части
команды (`executable_part`), простые команды делятся и по переводу строки. Репозиторий коммита —
каталог из разбора команды (`executable_commit_dir`, `cd` до вызова и `-C`, D1279): `cd <путь> && git commit`
и `git -C <путь> commit` судят названный репозиторий, каталог через переменную — папку сессии, `-a` в тексте сообщения и флаг соседней строки флагом
коммита не являются, упоминание «git commit» в кавычках коммитом не считается.
Первая редакция починки решала снимок на команду, а не на файл («есть `git add` — судить копию»),
и скептик показал, что она молчит чаще исправленного дефекта: по 1411 настоящим коммитам проекта
`git add` называет чужой путь у 398, половина переноса одной командой — у 162, голых коммитов 75.

Есть ли у проекта долг, решает HEAD, а не рабочее дерево: двери «файла нет — выходим» у
стража нет. `BACKLOG.md` удалён целиком (`rm`, `git rm`, переименование), а HEAD его несёт —
«после» пусто, и каждый пункт HEAD, которого нет в архиве, называется; у сообщения своя
строка («удалён целиком», совет `git checkout HEAD -- BACKLOG.md`), потому что объяснение
«перезапись куска файла» тут было бы неправдой. HEAD без `BACKLOG.md` либо без пунктов —
тишина: сторожить нечего.

**Нечитаемый бэклог — не пустой (D1121, 26 октября 2026).** `BACKLOG.md` есть, но не читается — страж говорит, что судить
нечем, и не называет пункты исчезнувшими: прежде «после» читалось пустым, и каждый пункт HEAD объявлялся пропавшим.
То же различение — у `backlog_read` (код 3: файла нет или он не читается).

**Повод.** Измерен на себе дважды за час 2026-08-26. Правка одного пункта делалась
заменой ДИАПАЗОНА текста — «от заголовка пункта до маркера в конце раздела» — и оба раза
уносила соседние пункты, попавшие внутрь границ: сперва D83/D85/D86 (коммит `6dffe5c`),
затем, уже после восстановления и разбора причины, снова D83/D86 (коммит `1fc183c`).
В архив они не попадали: это была не уборка, а перезапись куска файла.

**Почему хук, а не внимательность.** Приём с вычисляемыми границами выглядит безопасным
ровно до момента, когда между ними оказывается чужой текст, и увидеть это в момент
правки нечем — diff показывает результат, а не то, что пропало из середины. Второе
повторение в пределах часа означает, что правило в голове не держится
(`principle-knowledge-in-the-world`: уровень 1 хрупок, нужен уровень 3).

**Границы.** Смотрит только на идентификаторы вида `D<цифры>` в позиции пункта: пункт,
переименованный в другой идентификатор, будет назван пропавшим. Содержимое пункта не
сверяется — вычерпанный до одной строки пункт хук пропустит; это отдельный класс, и он
закрывается не здесь, а чтением diff. Форма команды разбирается не вся: пути читаются как слова
— glob кроме `BACKLOG*`, каталог кроме `.`, `git add -p`, `-i|-o|--include|--only`,
pathspec-магия и алиасы git не разбираются, а значение флага, совпавшее с существующим путём,
может быть принято за путь коммита (тогда файл судится по HEAD — молчание). Индекс в состоянии
конфликта и нечитаемый индекс не судятся: «не смог прочитать» иначе вышло бы «все пункты
исчезли». Условие снятия — разбор аргументов git у владельца области команд.
Сторожится только `BACKLOG.md`: пункт, стёртый из `BACKLOG-archive.md`, не называется.

Три предела удаления целиком названы в коде с условиями снятия. Первый: команда, которая
удаляет файл САМА (`git rm BACKLOG.md && git commit` одной строкой), стражу не видна —
PreToolUse читает дерево до её начала, а после такого коммита HEAD файла уже не несёт;
названы только двухшаговые формы (в 71 расшифровке проекта таких команд с `BACKLOG.md` 0
из 1632 с `git commit`). Второй: HEAD с незакрытым забором кода даёт пустое «до», и
страж молчит так же, как при HEAD без пунктов, — удаление целиком этим путём проходит
молча; здоровый образец (сверка сырого текста с очищенным) назван в коде стража. Третий:
рабочее дерево, где файл скрыт намеренно (sparse-checkout), будет названо на каждом
коммите; условие снятия — появится такой проект, тогда различать бит skip-worktree.
