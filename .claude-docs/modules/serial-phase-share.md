# serial-phase-share — доля последовательной фазы набора не растёт молча

**Назначение.** Раннер делит тесты на параллельную и последовательную фазы правилом
`needs_serial` из текста теста и делает это молча; очередь последовательных растёт вместе с
набором, а оптимизировать приходится задним числом. Замер называет долю последовательных тестов
и долю их времени числом; правило для автора теста — в `docs/development.md`, «Новый тест».

**Файлы.** `scripts/serial-phase-share.sh`; фазу печатает сам раннер — режим
`hooks/tests/run_all.sh --phases` («serial» либо «parallel» и имя через табуляцию), правило
`needs_serial` живёт только там; время — базис `state/suite-baseline.tsv`. Реестр замеров —
строка `serial-phase-share` (период 50 коммитов). Прибор `hooks/tests/test_serial_phase_share.sh`.
Рычаги: `SERIAL_SHARE_MAX` (20), `TESTS_DIR`, `SUITE_BASELINE_FILE`, `SERIAL_SHARE_LIST`.

**Показание 13 сентября 2026.** Тестов 504, последовательных 67 (13%); по базису последнего
полного прогона их время 188 с из 2832 с (6%). Первая сборка свидетеля дала 68 из 504: он сам
цитировал формы правила в фикстурах и ушёл в последовательную фазу — формы собраны из байтов.

**Коды.** 0 — доли названы, порог не превышен; 1 — доля последовательных выше порога
(находка: новые тесты берут общий ресурс без нужды); 2 — раннера или режима `--phases` нет.

**Названный предел.** Порог — доля по ЧИСЛУ тестов; доля времени печатается, но порога у неё
нет: базис пишется полным прогоном и на выборочных прогонах стареет. Условие снятия: базис
станет обновляться по каждому прогону теста, тогда порог по времени станет честным.

**Проверка.** `bash hooks/tests/test_serial_phase_share.sh` → 0.
