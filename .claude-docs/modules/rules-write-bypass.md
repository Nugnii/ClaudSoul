# rules-write-bypass

**Назначение.** Установленные глобальные правила (`~/.claude/CLAUDE.md`) правятся только
через библиотеку слияния. Прямая запись стирает маркеры управляемого блока, а без них
сверка дрейфа по паре «правила» не может состояться вовсе.

**Файлы.** `hooks/rules-write-bypass.sh`, тест `hooks/tests/test_rules_write_bypass.sh`
(9 проверок). Регистрация: `PreToolUse[Bash]`, в группе с `backlog-vanish-check` и `quality-gate-check`.

**Как работает.** На вызове Bash смотрит, трогает ли команда `.claude/CLAUDE.md`. Законный
путь проверяется ПЕРВЫМ: команда с `sync_claude_md`, `claude-md-merge` или `install.sh`
проходит без вопросов. Дальше отличает запись от чтения правилом, а не перечнем символов:
перенаправление В ФАЙЛ, `cp`/`mv`/`tee`/`install`, `sed -i`. Слияния потоков (`2>&1`,
`>&2`, `&>`) записью не считаются — иначе отказ приходил бы на чтение. Совпало —
`permissionDecision: deny` с готовой строкой правильного вызова в причине.

**Повод.** 28 августа 2026 пара «правила» в `drift-check` оказалась `BROKEN`: маркеров в
установленном файле не было, и сравнивать стало нечем. Шесть пар из семи сверялись,
седьмая — нет, то есть мастер-копия могла уехать от установленной сколь угодно далеко, и
ни один прогон бы этого не сказал. Дрейф означает «сравнили и разошлось»; здесь было
«не сравнивали вовсе».

**Почему беззащитна именно эта пара.** У остальных шести установка — побайтовая копия, и
любой обход ловится сравнением. Здесь установка ПРЕОБРАЗУЕТ содержимое (оборачивает в
маркеры), поэтому обход даёт не расхождение, а невозможность сравнить.

**Почему страж стал возможен только сейчас.** Пункт долга D101 отвергал его возражением
«правка идёт инструментом Edit, а хук `PreToolUse[Bash]` её не видит». Замер по пяти
сессиям: касаний `~/.claude/CLAUDE.md` через Bash — 23, через `Edit/Write` — 0. Возражение
снято данными, а не мнением, и ждать второго случая `BROKEN` стало незачем: ждали ради
выбора между тремя кандидатами, а выбор сделали числа.

**Названный предел.** Правка из другого процесса — редактором, файловым менеджером, чужим
скриптом — сюда не попадает: хук видит только вызовы Bash этой сессии. Для такого случая
остаётся `drift-check`, который скажет постфактум.

**Условие снятия.** Предел держится, пока единственный наблюдаемый вход — вызовы Bash этой сессии. Появится событие правки файла, видимое хуку независимо от процесса, — предел снимается и правка ловится в момент, а не постфактум.
