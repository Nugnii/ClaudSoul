# backlog-open-write-guard — открытый пункт долга получает красную «Проверку» в момент записи

**Назначение.** Контракт долга: у открытого пункта «Проверка» красна и исполнима — зелёная значит
«закрывай с показанием» либо «команда не о дефекте», отсутствующая — «критерия нет». До 13 сентября
2026 это называл только страж границы хода (`completion-gate`), ПОСЛЕ записи. Теперь запись
открытого пункта с зелёной или отсутствующей «Проверкой» отбивается отказом уровня 4 с именем
пункта (D264).

**Файлы.** `hooks/backlog-open-write-guard.sh` (PreToolUse на Edit|Write|MultiEdit по `BACKLOG.md`),
прибор `hooks/tests/test_backlog_open_write_guard.sh` (18 ног), разбор пунктов — седьмое поле
`backlog_open_items` в `hooks/backlog-lib.sh` (команда строки «Проверка.»), бюджет команды —
`hooks/timeout-lib.sh` (`OPEN_WRITE_TIMEOUT`, 20 с), журнал —
`state/backlog-open-write-fired-<SID>.jsonl` (семейство `*-fired-*`, читатель `signal-precision`).
Регистрация — `install.sh`, матчер `Edit|Write|MultiEdit`.

**Уровень 4 — по замеру, а не по вкусу.** Журнал исходов стража границы хода
`cg-open-fired.jsonl` на 13 сентября 2026: 23 срабатывания с исходом — confirmed 18, rewritten 5
(команда переписана по собственному предписанию канала), ложных 0. Порог ADR-015 (ложных ниже
десятой части при n ≥ 20) пройден. Признак с одним последствием: продолжение вызова положило бы
в долг открытый пункт без красного критерия.

**Что судится.** Новый текст файла собирается из payload (Write — целиком, Edit/MultiEdit —
правками к диску); сравниваются открытые пункты «до» и «после», и исполняются только те, чья
«Проверка» НОВА или ИЗМЕНЕНА. Неизменённые пункты — предмет `completion-gate` по сроку; иначе
каждая правка строки платила бы десятками команд. Закрытие пункта в той же правке (☐ → ☑)
проходит: закрытых страж не касается. Диск страж не трогает.

**Названные пределы.** Команда, не уложившаяся в бюджет, зелёной не доказана — не отказ, а
контекст и запись `timeout` в журнал (условие снятия — то же, что у бюджета вообще: команда
пункта обязана быть дешёвой). Правка бэклога через Bash (python-heredoc, sed) стражу не видна:
он стоит на инструментах записи; условие снятия — разбор целей записи у Bash-вызова с чтением
содержимого. Без jq, python3 или библиотек — тишина и код 0 (чужой проект, не отказ).

**Ноги прибора.** Отказ с именем и видом на новом зелёном (T1), красный проходит (T2), без
строки «Проверка» — отказ (T3), правка закрытого проходит (T4), неизменённый зелёный на диске
не судится (T5), Write: судятся только изменённые (T6), закрытие в правке проходит (T7), срыв
бюджета — контекст и журнал (T8), журнал отказа (T9), MultiEdit (T10), чужой файл и битый
payload (T11), диск не тронут (T12).

**Проверка.** `bash hooks/tests/test_backlog_open_write_guard.sh` → 0.
