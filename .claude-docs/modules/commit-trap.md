# commit-trap — ловушки git стражей коммита

**Назначение.** Стражи коммита судят тот коммит, который сделает git: в его репозитории, по его индексу и сообщению.
Коммит в другой репозиторий не получает отказа по состоянию папки сессии и не меняет её индекс (D1022).

**Файлы.** `hooks/commit-trap.sh` (установка и обе ловушки), `project_commit_trap` в `hooks/paths-lib.sh` (стоит ли
ловушка в репозитории каталога), режимы `--commit-msg <файл>` у `merge-root-gate`, `docs-family-check`,
`doc-impact-check`, `backlog-vanish-check`, `changelog-reminder` и `--pre-commit` у `doc-impact-check`. Тест —
`hooks/tests/test_commit_trap.sh` (48 проверок; на стражах без режима ловушки краснеют 7, каждая из девяти мутаций
находок скептика D1022 и каждая мутация починок D1023 краснит свою ногу), пробы
`hooks/tests/fixtures/probe_D1022.sh` и `probe_D1023.sh`. В настройках Claude Code не регистрируется: её зовёт git.
Отметку проверки коммита пишет `scripts/commit-stamp.sh` (свидетель `hooks/tests/test_commit_stamp.sh`).

**Почему ловушка, а не разбор команды.** На PreToolUse стражи восстанавливали коммит из текста команды: репозиторий —
по папке сессии, файлы — по `git add` той же строки, сообщение — по `-m`. Универсум форм команды открыт (корень R3):
`git -C <другой> commit` получал отказ по автотаблицам ClaudSoul, пересборка учёта клала `.claude-docs/dep-index.tsv`
в индекс папки сессии, `doc-state:` в файле `-F` не был виден. Владелец этих фактов — git; его ловушки получают их
готовыми (решение владельца 21 октября 2026 «Тоже в ловушку git», как суд корня в D1021).

**Как работает.**
- `commit-msg` зовёт стражей по очереди; первым — суд корня. Отказ стража в ловушке — код `CT_REFUSE_RC` (10), и
  коммит не выполнен, причина в stderr. Подсказки печатаются в stderr при коде 0: агент видит их в выводе команды, как
  прежде видел `additionalContext` после вызова.
- `pre-commit` — только пересборка учёта зависимостей в индекс коммита: git строит дерево после pre-commit и до
  редактора, и `commit-msg` состав коммита уже не меняет. Коммит путями (`git commit <пути>`) git собирает во
  временном индексе и после коммита возвращает основной таким, каким подготовил до ловушки, — учёт, добавленный в
  коммит, следующий коммит откатил бы. Поэтому при коммите путями учёт не пересобирается, а называется командой.
- Код 1 bash даёт и сам, падая (`set -u`, нет библиотеки), поэтому страж с кодом вне {0, `CT_REFUSE_RC`} называется в
  stderr («упал») и коммит не держит. Исключение — суд корня: у него «прибор сломан» — отказ (D1021), и любой его
  ненулевой код держит коммит.
- На PreToolUse четыре стража молчат, когда ловушка СУДИТ этот коммит (`project_commit_trap`): шим `commit-msg` несёт
  метку `claudsoul-commit-trap` с адресом после `@ `, файл по адресу на месте, и команда не обходит ловушку
  (`--no-verify`, `-n` коммита, `core.hooksPath`, `GIT_CONFIG_*`, `alias.`). Мёртвая ловушка и обход возвращают суд
  PreToolUse; где ловушки нет, стражи судят по-прежнему (решение владельца 22 октября 2026 «Оставить как сейчас»).
- Строки-комментарии сообщения (`#`) не считаются ни решением `doc-state:`, ни заявлением «закрыт»: в режиме
  очистки git их вырежет.

**Установка.** `bash hooks/commit-trap.sh --install <репозиторий>` (то же — `merge-root-gate.sh --install`). Шим несёт
обе метки, `claudsoul-commit-trap` и `claudsoul-merge-root-gate`, адрес `commit-trap.sh` той установки, из которой
ставился, и свой заголовок второй строкой. Своим установка считает только файл с этим заголовком (либо заголовком
ловушки D1021) и только его переписывает; в чужой ловушке называет строку для дописки (код 2), а дописанную строку не
трогает. Каталог ловушек внутри рабочего дерева (`core.hooksPath` на папку проекта) — отказ: шим лёг бы файлом
проекта.

**Цена.** Проверки судят и ручные коммиты владельца в терминале: подсказки печатаются, отказ автотаблиц коммит не
пропускает (названо владельцу при решении).

**Обход ловушки (D1023).** Решение владельца 22 октября 2026 «Только след в git»: обход `commit-msg` судится по следу,
а не по слову в команде. `commit-msg`, пропустив коммит, пишет след «<pid git> <дерево индекса>»
(`--git-path claudsoul-trap-pass`). `post-commit` git исполняет и при `--no-verify`/`-n` в любом написании, включая
псевдоним, и в `cherry-pick`: нет следа этого процесса git с этим деревом — обход; коммит агента (окружение
`CLAUDECODE` или `AI_AGENT`) судит суд корня (`merge-root-gate.sh --judge-commit`; коммит без родителя — от пустого
дерева), и непропущенный снимается `reset --soft HEAD@{1}` — изменения остаются в индексе. Коммит владельца в
терминале не судится: `--no-verify` — его право. Первая редакция ставила ещё сверку вершин main до и после команды
агента; финальный скептик показал, что откат «к вершине до команды» уносит законные коммиты параллельной сессии и
подтянутую чужую работу, и владелец выбрал оставить один `post-commit`: он снимает только коммит своего процесса git.

**После коммита — архивные «Проверки» фоном (D1249, решение владельца 8 ноября 2026).** `post-commit` основного
репозитория ClaudSoul (вершина коммита — корень ClaudSoul по физическому пути; клоны и рабочие копии `git worktree`
не зовут) отсоединённым процессом запускает `scripts/archive-checks-after-commit.sh` — «Проверки» закрытых пунктов,
задетые файлами коммита; не держатся — строка в очереди напоминаний. Запуск идёт без переменных `GIT_*`: процесс
ловушки git унаследовал бы GIT_DIR коммита, и `git init`/`git config` проб ушли бы в этот репозиторий (инцидент
8 ноября 2026 — проба D515 вписала `core.bare = true`). Коммит прибора не ждёт.

**Сдвинутые адреса строк (D1251).** `commit-msg` после стражей зовёт `scripts/line-address-drift.py --staged` (у
ClaudSoul, ADR-018): адреса «файл:строка», которые коммит не тронул, а строку под ними сдвинул, печатаются подсказкой в
stderr — до 20 строк и числом остальных. Коммит подсказка не держит. Описание — `.claude-docs/modules/line-address-drift.md`.

**Отметка проверки коммита (решение владельца 18 ноября 2026).** Приём из статьи команды Claude Code «How the Claude
Code team thinks about verification»: у каждого коммита отметка, как он проверен, включая «ничем», чтобы непроверенные
можно было спросить. `post-commit` у коммита агента (CLAUDECODE или AI_AGENT) в любом репозитории с ловушкой
отсоединённым процессом зовёт `scripts/commit-stamp.sh --record` — коммит не ждёт. Прибор читает расшифровку сессии
`CLAUDE_CODE_SESSION_ID` и её субагентов и в окне от времени родителя коммита, по строкам с `cwd` в репозитории
коммита, считает вызовы критика (агент, в начале промпта которого «противник», «скептик» или «критик»; скилл
`adversary`/`code-review` — шире признака `adversary-run-lib.sh`, который видит только `/adversary`) и вызовы Bash с
тестом. Строка журнала
`state/commit-stamps.tsv`: коммит, время, репозиторий, сессия, критик, тесты, отметка — `критик+тесты`, `критик`,
`тесты`, `ничем` или `не прочитано` (расшифровки нет или она не разобрана; это не «ничем»). Запрос —
`bash scripts/commit-stamp.sh --unverified [<репозиторий>] [N]`; коммит без строки (владельца в терминале, мимо ловушки)
`--list` называет «не отмечен». РЕЖИМ НАБЛЮДЕНИЯ: отказа нет; отказ по отметке — отдельное решение владельца по числам
журнала. Пределы: оба признака — перечни форм (R3), точность не измерена; «тесты» значит «прогон был», а не
«зелёный»; окно — от родителя (у коммита без родителя — вся сессия); критик из другой сессии не засчитывается.
Свидетель — `hooks/tests/test_commit_stamp.sh`: самопроверка прибора (девять случаев; семь мутантов прибора краснят её)
и сквозной коммит через установленную ловушку (без вызова краснеет нога E1, синхронный вызов — нога E4). Финальный
скептик opus 18 ноября 2026 нашёл в первой редакции два H (скептики проекта не считались критиком, расшифровки
субагентов не читались) и три M; исправлены до коммита.

**Пределы.** Формы, выключающие все ловушки разом (`core.hooksPath`, `commit-tree` + `update-ref`, `update-ref` и
`push .` в main), и намеренная подделка улик агентом (окружение, след) не судятся: агент, решивший обмануть, может
переписать и сам страж; без журнала ссылок (`core.logAllRefUpdates=false`, первый коммит, коммит после удаления
ветки) обход называется, а не снимается — прежняя вершина неизвестна; стражи-подсказки на обходе молчат —
`post-commit` судит только корень; `rebase` на main (вершина отсоединена) и слияния ловушки не судят (слияния —
PreToolUse merge-root-gate); `revert`, `am` не проверены; при `--amend` стражи-подсказки сравнивают индекс с HEAD, а не с HEAD^;
при коммите путями учёт не пересобирается; при чужой `pre-commit` учёт не пересобирается вовсе (отчёт называет
команду); комментарий сообщения узнаётся по `#`, а не по `core.commentChar`; в режиме `--cleanup=verbatim` решение в
строке `#` останется в сообщении, а подсказка выйдет; журнал решений `doc-state` в ловушке пишется по дням
(`doc-state-git-trap-<дата>.jsonl`), а не по сессиям — сессии ловушка не знает.
