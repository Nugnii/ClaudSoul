# denied-branch-commit-guard — коммит не уходит молча мимо ветки, создание которой отклонено

**Назначение.** Отказ на `git commit`, если отклонённый стражем вызов Bash создавал ветку X (`git switch -c|-C|--create|--force-create|--orphan`, `git checkout -b|-B|--orphan`, `git worktree add -b`, в том числе склеенные `-qc X`, `-bX`, `--create=X`), а коммит идёт не на X. Отказ стража отменяет вызов целиком, вместе с безвредным созданием ветки, а намерение агента «я на ветке X» переживает отказ. Отказ — один на каждый отклонённый вызов (ключ — его `tool_use_id`): повтор той же команды проходит.

**Молчит**, когда условие коммита утверждено или предмета нет: команда коммита сама переключает ветку (`git switch X && … git commit`; отметка не ставится — переключение может не случиться); HEAD каталога коммита — X (отказ отработан, отметка); отклонённый вызов и коммит — в разных репозиториях или копиях, либо каталог отказа не установлен; создание ветки стоит в отклонённой цепочке ПОСЛЕ коммита. Сломанный разбор (исключение питона) — сигнал `additionalContext` «прибор сломан», а не тишина.

**Файлы.** `hooks/denied-branch-commit-guard.sh` (PreToolUse на `Bash`; регистрация — `install.sh`), тест `hooks/tests/test_denied_branch_commit_guard.sh` (35 ног: из них 22 — атаки трёх раундов противника). Отметки — `state/denied-branch-commit-<SID>-<cksum id отказа>`, создаются атомарно (`set -C`).

**Зависимости.** `jq`, `python3`; владельцы фактов: разбор команды — `hooks/lib/write_targets.py` (`git_calls`: кавычки, heredoc, позиция команды, `cd` и `-C`, склеенная пунктуация, обёртки), «это коммит» — `is_git_commit` (`hooks/command-scope-lib.sh`), отказ — `hooks/lib/deny_mark.py` (с префиксом харнесса — D527), git в папке сессии — `project_git`. Каталог отклонённого вызова — поле `cwd` строки расшифровки плюс `cd`/`-C` команды.

**Почему отказ, а не подсказка.** Подсказка PreToolUse доставляется вместе с результатом вызова, то есть после коммита. Последствие продолжения одно — коммит в другую ветку.

**Чем решалось раньше.** Знание `pattern-commit-condition-lives-in-the-command` и кейс `case-2026-10-11-denied-chain-left-commits-on-main-gate-passed-missing-branch` — уровень 1-2, привычка «ветку создавать отдельной командой». Остаются как объяснение.

**Противник, три раунда (11 октября 2026).** Раунд 1 сломал первую редакцию (регулярное выражение по тексту с вырезанными кавычками): молчала на собственном поводе `git switch -q -c` (узнавала 9 форм создания ветки из 85 в корпусе), отбивала повтор цепочки и коммиты в чужом репозитории. Раунд 2 — входы закрытых классов и новые: if/while/until, `checkout -- файл`, сломанный прибор молчал. Раунд 3 (предел скилла) — последствия правки «отметка на молчании»: отметка по имени ветки глушила повтор отклонённой цепочки и отказ в другом репозитории; «X существует» принималось за «HEAD был на X». Отсюда ключ по `tool_use_id` и отметка только на проверенном исходе.

**Названные пределы.** Расшифровка читается с хвоста (`DBC_WINDOW`, 3000 строк). Не разбираются: `pushd`, `cd -`, `GIT_DIR=`/`--git-dir=` как каталог коммита; `git branch X && git switch X` как создание; `#` внутри имени ветки. Подстановки в кавычках, `bash -c '…'` и `eval '…'` раскрывает владелец разбора (`git_calls`, D1323). `git checkout <файл>` без `--` считается переключением ветки. `cherry-pick`/`merge`/`revert`/`am` коммитом не считаются (судит `is_git_commit`). Расшифровка, которую хук получает внутри субагента, не проверялась.

**Повод.** ProjectA 11 октября 2026 (D526): `git switch -q -c fix/blind-stretches && …` отклонён гейтом разбора, правка повторена отдельно, ветка — нет; два коммита легли в main.
