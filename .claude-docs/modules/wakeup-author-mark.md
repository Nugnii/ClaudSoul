# wakeup-author-mark — ход побудки узнаётся служебным по тексту, который запланировал сам агент

**Назначение.** Хуки подачи реплики судят модель собеседника (авторизацию, состояние, цену момента) по тексту хода. Ход
побудки `ScheduleWakeup` приходит им как обычная реплика: текст пишет сама модель, формы у него нет, вход хука автора не
несёт (замер зондом 8 ноября 2026 — 8 полей, `isMeta`/`origin` нет), а текущей реплики в расшифровке на подаче ещё нет.
Автор хода известен в одном месте — в вызове `ScheduleWakeup`: этот хук на PreToolUse записывает сумму текста `prompt`,
и признак служебного хода `is_non_user_turn` (`hooks/hook-input-lib.sh`) узнаёт по ней ход побудки на подаче.

**Файлы.** `hooks/wakeup-author-mark.sh` (PreToolUse, отбор `ScheduleWakeup`; регистрация — `install.sh`), проба
`hooks/tests/fixtures/probe_D1247.sh`. Состояние — `state/wakeup-prompts.tsv`, строка «сумма `cksum` ⇥ время», только
дописывается.

**Зависимости.** `jq` (без него хук молчит); читатель записи — `is_non_user_turn`, за которым стоят трекер
интрузивности, детектор событий и авторизация, языковые хуки и другие хуки подачи.

**Правила.**
- Ход побудки приходит с текстом вызова побайтно: в корпусе 3 хода из 3 совпали по сумме с `prompt` своего вызова.
- Файла нет — сверка в `is_non_user_turn` не делает ничего (без побудок цена 0); форма реплики судится раньше суммы.
- Узнаётся только запись моложе двух часов: `ScheduleWakeup` откладывает не дольше часа, идущий цикл пишет запись на
  каждой побудке, а в штатном `/loop` текст побудки — команда владельца, и её повтор позже остаётся поручением.

**Молчит.** Вызов не `ScheduleWakeup`; пустой `prompt`; нет `jq`.

**Названные пределы.** Реплика владельца, побайтно равная запланированной побудке, будет принята за побудку. Сторожевое
`<<autonomous-loop-dynamic>>` харнесс подменяет инструкциями — такой ход суммой не узнаётся. Файл общий для сессий и
растёт на строку за побудку (около 20 байт). Сам ход побудки зондом не вызван — `ScheduleWakeup` только для `/loop`;
равенство текста подачи и текста вызова измерено по расшифровке, а не по входу хука.

**Повод (D1247).** Финальный скептик D1207 (4 ноября 2026): 3 хода побудки в одной расшифровке, на копии детектор взвёл
авторизацию `task:content` из слов агента.
