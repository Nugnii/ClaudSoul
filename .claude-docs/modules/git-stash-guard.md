# git-stash-guard — `git stash` не трогает рабочую копию общей папки

**Назначение.** Отказ на вызов Bash, в котором оболочка исполнит `git stash` в любой форме, кроме `list` и `show` (голый, `push`, `pop`, `apply`, `drop`, `clear`, с флагами, через `git -C`, после обёрток и разделителей). Последствие продолжения одно: рабочая копия папки, в которой работают параллельные сессии и фоновые прогоны, меняется, а `pop` достаёт верхнюю запись, не обязательно свою. Отсюда уровень 4 — решение владельца 11 октября 2026 (D525).

**Файлы.** `hooks/git-stash-guard.sh` (PreToolUse на `Bash`; регистрация — `install.sh`), тест `hooks/tests/test_git_stash_guard.sh` (59 ног: отказы, молчания, перенос строки, текст замены, журнал, сломанный прибор). Журнал срабатываний — `state/git-stash-fired-<SID>.jsonl`, семейство `*-fired-*`.

**Зависимости.** `jq`, `python3`; разбор команды — `git_calls` у владельца лексики оболочки `hooks/lib/write_targets.py` (кавычки, тела heredoc, позиция команды, глобальные опции git, перенаправления, склеенная пунктуация, перенос строки, обёртки) — за один проход. Правило «меняет рабочую копию» (любая форма, кроме `list` и `show`) — `stash_changes` там же: его зовёт и признак «вызов пишет» стража разбора (D1215). Предфильтр — подстрока `stash` в команде. Без `python3` или библиотеки страж молчит (инструмента нет); исключение питона — сигнал `additionalContext` «прибор сломан», а не тишина.

**Замена (в тексте отказа).** Код до правки — `git show HEAD:<путь>` или отдельная копия `git worktree add --detach <каталог> HEAD`; отложить правки — коммит в ветку; посмотреть записи — `git stash list` / `git stash show`.

**Чем решалось раньше.** Текстом: «не stash во время фонового прогона» (SESSION.md ProjectA), память `feedback_stash_push_pop_pops_foreign`, кейс `case-2026-10-11-git-state-assumed-after-chained-command-three-slips` — три нарушения. Остаются как объяснение; страж держит путь.

**Замер до включения.** 320 расшифровок: 211 вызовов с `git stash`, из них `list` 56, `show` 4, остальное меняет рабочую копию; около половины — в самом ClaudSoul (сравнение «до правки»).

**Противник.** Раунд 1 сломал первую редакцию (`is_git_subcommand` + своя копия опций git в sed, два прохода `executable_part`): ложные отказы на `git -C "<путь>" stash list`, `--no-pager`, `list>файл`; пропуски `it\'s; git stash pop`, `=$(git stash pop)`, `"git" stash`. Раунд 2 — расхождения лексера `shlex` с bash у владельца разбора (склеенная пунктуация, перенос строки, `#` внутри слова), обёртки, незнакомые опции git, молчание сломанного прибора. Раунд 3 — регрессия правок раунда 2: комментарий отрезался после снятия кавычек (`git commit -m "#123"; git stash pop` проходил), апостроф в комментарии глотал строки; перенос без отступа, перенаправления, кубическая цена. Починено у владельца: комментарий, перенос и граница команды — проходом по сырому тексту с учётом кавычек, затем один проход лексера. Всё закреплено ногами (59); правки лексера получил и сосед `denied-branch-commit-guard`.

**Названные пределы.** Скрипт, внутри которого стоит `git stash`, не виден: судится команда вызова. `bash -c '…'`, `eval '…'`, обратные кавычки и подстановки в кавычках раскрывает владелец разбора (D1323); чужие интерпретаторы (`python3 -c`, `xargs sh`) и подстановки в теле heredoc без кавычек в метке не раскрываются. Команда, которую лексер не разбирает (незакрытая кавычка), проходит. `git stash --help`, `git stash create` отбиваются (rule_choice: читающих форм две — `list`, `show`).
