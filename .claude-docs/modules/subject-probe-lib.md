# subject-probe-lib — выхолащивание предмета, один владелец на всех

**Файл:** `hooks/subject-probe-lib.sh`
**Потребители:** `scripts/behavior-condition-probe.sh` (прибор ложной зелени),
`scripts/witness-subject-propose.sh` (объявлятель предмета)
**Свидетели:** `hooks/tests/test_behavior_condition_probe.sh` (через прибор, ноги T10b/T11b
мутируют саму библиотеку), `hooks/tests/test_witness_subject_propose.sh`

## Зачем

Приём «выхолостить предмет и посмотреть, покраснеет ли свидетель» жил внутри цикла прибора
единственным местом. 22 сентября 2026 (D474) у него появился второй потребитель, и копия
дала бы факту «как выхолостить предмет» двух владельцев, расходящихся молча (корень R1):
видов предмета три — список через пробел, каталог с косой, одиночный файл, — и правка
любого из них прошла бы мимо второй копии. Предшественник снят, прибор ЗОВЁТ библиотеку.

## Договор

`sp_hollow_run <снимок> <свидетель> <предмет> <файл вывода>` → код прогона свидетеля на
выхолощенном предмете: `9` — выхолостить не удалось (предмета нет, копия не легла),
прочее — код самого свидетеля.

**Смысл кода решает ЗОВУЩИЙ, а не библиотека.** У прибора `0` значит обвинение («зелен на
мёртвом предмете»), у объявлятеля ненулевой значит находку («этот кандидат и есть предмет»).
Функция не судит и не считает — иначе у двух потребителей с обратными направлениями
вердикта пришлось бы заводить два режима, то есть тот же R6 внутри самой библиотеки.

## Срок свидетеля — из его базиса

`_sp_deadline` спрашивает `deadline_for_test` (`hooks/timeout-lib.sh`, владелец расчёта,
общий со сторожем набора) и обрезает ответ потолком `SP_WITNESS_CAP` (240 с).

Зачем (23 сентября 2026, D474): общий срок 30 с ловил тех, кто дорог ПО ПРИРОДЕ — замер дал
17 «не уложившихся», и у части базис набора заведомо выше (`test_defect_registry_cache`
228 с, `test_docs_match_tree` 109 с). Прибор называл нагрузкой цену теста и лишал его
вердикта, то есть `judged` не догонял `resolved` по причине, не имеющей отношения к предмету.

Потолок ниже потолка набора намеренно: прибор гоняет каждого свидетеля до двух раз и
проходит шестьсот штук, поэтому расчётные 684 с (228 × 3) увели бы прогон в часы.
Цена названа: прогон дорожает на сумму базисов этих свидетелей — порядка десяти минут.

Свидетеля нет в базисе — остаётся `SP_WITNESS_TIMEOUT`, то есть прежнее поведение.

## Названные свойства

- **Заглушка не меняет поток управления зовущего.** Выхолощенный файл — `:` для shell,
  `pass` для python: запущенный как программа даёт 0, источённый не объявляет ни одной
  функции. Заглушка с `exit 0` завершала бы САМ тест нулём при `source` — зелёный по
  построению.
- **Мир судимого теста привязан к песочнице** (`CLAUDSOUL_REPO`/`CLAUDSOUL_ROOT`): без
  привязки тест резолвит предмет в настоящем репозитории, где тот цел. Род M реестра.
- **Свидетель запускается без чужого stdin** (22 сентября 2026). Зовущий идёт циклом
  `while read` по перечню, и запущенный тест наследует этот перечень своим стандартным
  входом: читающий stdin выпивает остаток очереди, цикл кончается раньше срока и выходит
  нулём. Замер: объявлятель обработал 10 свидетелей из 52 — недосчёт был неотличим от
  «работа сделана».

## Снимок, срок и откат — три договора, добавленные противником (22 сентября 2026)

**`sp_snapshot <куда>`** — снимок собирается клоном (история нужна: часть свидетелей берёт
положительный контроль через `git show`) И накрывается нынешним содержимым рабочего дерева
(`git ls-files -co --exclude-standard`). Прежде у факта «что сейчас в дереве» было два
владельца: вселенную перечисляли глобом по рабочему дереву, а судили `git archive HEAD`.
Цена расхождения измерена двумя атаками: объявление на незакоммиченный механизм роняло ВЕСЬ
прибор кодом 2, а объявлятель предлагал предмет, вычитанный из коммита, файлу, который с тех
пор судит другое, — то есть сам производил ложную зелень, ради поиска которой построен прибор.

**`sp_run_witness`** — срок ставит владелец `hooks/timeout-lib.sh`; его отсутствие даёт код 2
и слова, потому что тихая работа без сторожа обещала бы защиту, которой нет. Умолчание —
потолок прибора, 240 с (с 8 ноября 2026, D1222; прежде 30 с): его получают свидетели БЕЗ строки
базиса — пробы `probe_*.sh` набор не гоняет, — и меньший срок ужесточал бы им срок вопреки
договору `deadline_for_test` «нехватка данных не ужесточает срок»; договор самих проб — срок
«Проверки» при перепроверке архива (300 с), а самые дорогие идут 120–150 с. Он же — потолок расчёта
по базису под нагрузкой. Замер: «не уложился» при 30 с — 14, при 60 с — 6. Код 124 от честного
падения не отличается намеренно: обоим потребителям это «свидетель не зелен».

**Что подменил — то и верну, на каждом выходе.** В ветке списка стояло `rm -f $_kept`: копии
уже подменённых файлов СТИРАЛИСЬ вместо возврата, и снимок оставался с заглушками, а прибор
продолжал судить по нему остальных. Повторённый в объявлении путь копировал в `.keep` уже
заглушку, затирая настоящую копию, — и прогон отвечал НУЛЁМ при навсегда выхолощенном файле.

**Каталог выхолащивается ЦЕЛИКОМ** (22 сентября 2026): прежде брались только `.sh` и `.py`,
а каталог объявляют предметом там, где механизм размазан, и часть его бывает ДАННЫМИ — у
конфига публикации это `exclude.txt`, `forbidden.txt`, `redact.sed`. Для данных заглушка —
пустой файл: «правил нет» и есть их мёртвое состояние. Свидетель, звавшийся ложно-зелёным,
оказался честным — виноват был приём.

**Символическая ссылка выхолащивается САМА**: запись сквозь неё портила ЦЕЛЬ, а возврат
клал на её место обычный файл — снимок оставался испорченным для всех следующих свидетелей.
Носителей в дереве нет (`git ls-files -s` без записей 120000), класс достижим с первой ссылки.

**`sp_run_witness_bare <снимок> <свидетель> <файл вывода>`** — прогон БЕЗ привязки корня
(22 сентября 2026). Не замена основному, а второй инструмент: привязка лечит род M и снимать
её нельзя, но у части свидетелей она отбирает предмет. Один код возврата отвечал за два
состояния — «свидетель сломан» и «привязка отобрала у него предмет», — и различить их можно
только чистым прогоном. Волна разбора назвала таких поимённо: восемь свидетелей, вне прибора
все зелёные.

**`sp_witness_run`** — развилка режима: `SP_BARE=1` ведёт прогон через `sp_run_witness_bare`,
иначе через `sp_run_witness`. Режим выбирает ЗОВУЩИЙ по своему измерению, библиотека лишь
исполняет: она не знает, почему свидетель красен, и не решает за прибор. Смысл развилки —
весь суд в ОДНОМ окружении: судить предмет в одном мире, а предпосылку в другом значило бы
сравнивать разное.

## Адресация

Потребитель берёт библиотеку у КАТАЛОГА СЕБЯ (`dirname $0/../hooks`), а не через `$REPO`:
там `$REPO` значит «дерево, которое судим», и резолв через него искал бы своё имущество в
песочнице, где его нет по построению. Отсутствие библиотеки — не «другой проект», а
сломанная своя установка: код 2 и слова, потому что молчание читалось бы как «чисто».
