# Decompose — Task Decomposition

**Type:** worker

Разложи задачу на шаги ПЕРЕД тем как начинать. Не давай себе начать работу без плана если задача > 3 шагов.

## Зачем

| Без декомпозиции | С декомпозицией |
|-----------------|-----------------|
| Начал делать → застрял → переделал | Знаешь все шаги до начала |
| "Ещё одна маленькая вещь" × 10 | Scope зафиксирован |
| Забыл обновить X после Y | Зависимости явные |
| Нельзя показать прогресс | Прогресс = N/M шагов |

## Step 1: Complexity Check

Быстрая оценка — нужна ли декомпозиция:

| Шагов | Решение | Форма |
|-------|---------|-------|
| 1-3 | Не нужна. Делай сразу | — |
| 4-7 | Лёгкая декомпозиция (список шагов) | В чате |
| 8+ | Полная декомпозиция (шаги + зависимости + milestones) | **Артефакты** (Step 2a) |

## Step 2a: Артефакты (только 8+ шагов)

**MANDATORY READ:** Load `references/artifact-templates.md` — шаблоны spec.md / plan.md / tasks.md.

Для полной декомпозиции план живёт не в чате, а в файлах:

```
<корень проекта>/.claude-docs/specs/<YYYY-MM-DD>-<slug>/
├── spec.md    # ЧТО и ЗАЧЕМ (требования, demand, критерий успеха)
├── plan.md    # КАК (решения, gates, шаги, milestones)
└── tasks.md   # Исполняемые задачи со статусами
```

Порядок: **spec → clarify → plan → tasks**.

1. **spec.md** — требования без технических решений. Каждая ассумпция = маркер
   `[NEEDS CLARIFICATION: вопрос]`.
2. **Clarify-гейт:** пока в spec.md есть маркеры — задавай вопросы пользователю,
   вписывай ответы, снимай маркеры. К plan.md не переходить с открытыми маркерами.
3. **plan.md** — технические решения с трассировкой к требованиям + Pre-Implementation
   Gates (Surgical scope / No speculative features / Simplicity). Отступление от gate —
   обоснование в Complexity Tracking, не молчаливое игнорирование.
4. **tasks.md** — задачи со статусами, синхронизированы с TaskCreate (Step 6).

**Регенерация вниз:** изменилось требование → перегенерируй plan и tasks от спеки.
Правка tasks.md руками в обход плана — анти-паттерн. Для задач 4-7 шагов артефакты
НЕ создавать — чат достаточен, церемония дороже пользы.

## Step 2: Scope — что входит, что нет

```
📋 SCOPE
Входит:
- [конкретный результат 1]
- [конкретный результат 2]

НЕ входит:
- [что явно исключаем]
- [что можно сделать потом]
```

Scope = контракт. После фиксации — не расширять без явного решения.

## Step 3: Декомпозиция на шаги

Для каждого шага:

| Поле | Что |
|------|-----|
| **#** | Номер |
| **Что** | Конкретное действие (императив) |
| **Результат** | Артефакт: файл, коммит, проверка |
| **Зависит от** | Номера предыдущих шагов (если есть) |
| **Оценка** | quick (< 5 мин) / medium (5-20 мин) / heavy (> 20 мин) |

```
📋 ПЛАН — [задача]
━━━━━━━━━━━━━━━━━

| # | Что | Результат | Зависит от | Оценка |
|---|-----|-----------|-----------|--------|
| 1 | ... | ... | — | quick |
| 2 | ... | ... | 1 | medium |
| 3 | ... | ... | 1 | quick |
| 4 | ... | ... | 2, 3 | heavy |
```

## Step 4: Milestones (для 8+ шагов)

Группировать шаги в milestones — промежуточные точки, где можно остановиться:

```
Milestone 1: [название] — шаги 1-3
  Проверка: [что должно работать]
  
Milestone 2: [название] — шаги 4-6
  Проверка: [что должно работать]
```

Milestone = точка, где система стабильна. Можно коммитить, можно прервать.

## Step 5: Параллелизм

Найти шаги без взаимных зависимостей → можно делать параллельно:

```
Параллельно: шаги 2 и 3 (оба зависят от 1, не друг от друга)
Последовательно: 4 после {2, 3}
```

## Step 6: Создание tasks

Для каждого шага — создать task (TaskCreate):
- subject = действие из "Что"
- description = результат + зависимости
- Зависимости через addBlockedBy

## Step 7: Показать план

```
📋 ДЕКОМПОЗИЦИЯ — [задача]
━━━━━━━━━━━━━━━━━━━━━━━

Scope: [1-2 строки]
Шагов: N | Milestones: M | Параллельных: K
Оценка: [суммарная]

[таблица шагов]

[milestones если есть]

Начинаю с шага 1. Подтвердить?
```

## Rules

- Не начинать execution до подтверждения плана (для задач 8+)
- Для задач 4-7 — показать план, но можно начать сразу
- Scope не расширять без явного решения
- Каждый шаг = проверяемый результат (не "подумать о X")
- Milestones = точки коммита (не абстрактные фазы)
- Параллелизм = реальная возможность (не оптимистичное "можно всё сразу")
- Если в процессе выяснилось что нужен новый шаг → добавить явно, не молча
- (8+) К plan.md не переходить, пока в spec.md есть [NEEDS CLARIFICATION]
- (8+) Не прошёл Pre-Implementation Gate → упрости план или обоснуй в Complexity Tracking
- (8+) Изменение требований → регенерация spec → plan → tasks, не точечные правки tasks

## Definition of Done

- [ ] Complexity check выполнен
- [ ] Scope зафиксирован (что входит / не входит)
- [ ] (8+) Артефакты созданы: spec.md, plan.md, tasks.md в .claude-docs/specs/
- [ ] (8+) Маркеры [NEEDS CLARIFICATION] закрыты до плана
- [ ] (8+) Pre-Implementation Gates пройдены или отступления в Complexity Tracking
- [ ] Шаги определены с результатами и зависимостями
- [ ] Milestones определены (если 8+ шагов)
- [ ] Параллелизм выявлен
- [ ] Tasks созданы
- [ ] План показан пользователю
