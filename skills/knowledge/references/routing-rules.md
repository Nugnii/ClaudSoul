# Routing Rules — Knowledge Coordinator

## Severity Assessment для capture

### Deep (/retro) — когда:
- 3+ попыток починки одной проблемы
- Корневая причина неочевидна (потребовался анализ)
- Цепочка связанных ошибок (одна тянет другую)
- Фундаментальное непонимание (не опечатка, а неверный подход)
- Impact ≥ 3 (серьёзная переделка или потеря данных)

### Quick (/learn) — когда:
- 1-2 попытки, быстро нашли причину
- Причина понятна, правило очевидно
- Коммуникативный инсайт (коррекция, аналогия)
- Успешная стратегия, которую стоит запомнить
- Impact 1-2

### Skip — когда:
- Тривиальная опечатка, исправлена за секунды
- Знание уже существует в базе (проверить!)
- Повторение уже записанного кейса без нового инсайта

## Type Detection

| Сигнал в контексте | Тип |
|-------------------|-----|
| Bash error, stack trace, неработающий код | `error` |
| Собеседник поправил, удивил, дал аналогию | `communication` |
| Задача решена чисто, подход сработал | `success` |
| Собеседник явно указал тип | Использовать указанный |

## Audit Routing

| Сигнал | Worker | Аргумент |
|--------|--------|----------|
| "проверь знания", "аудит" | /knowledge-audit | quick |
| "полный аудит", "детально" | /knowledge-audit | full |
| "мосты", "связи между слоями" | /bridge-health | all |
| "мост L2-L3", конкретный мост | /bridge-health | L2-L3 |
| "здоровье системы" | /knowledge-audit + /bridge-health | quick + all |

## Priority при конфликте

Если несколько сигналов одновременно:
1. **Error capture** (пока свежо в контексте) > audit
2. **Communication capture** (инсайт может потеряться) > audit
3. **Audit** > health (аудит шире)
4. **User explicit request** > любой auto-routing
