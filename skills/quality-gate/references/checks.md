# Quality Gate — Checks Reference

## Universal Checks (всегда)

### 1. DoD выполнен
- Если задача из скилла → прочитать его `## Definition of Done`, все чекбоксы должны быть ✅
- Если задача из плана → проверить описание в PLAN.md
- Если свободная задача → проверить что результат соответствует запросу

### 2. Код работает
- Если есть тесты → `npm test` / `pytest` / аналог проходит
- Если UI → Playwright verify или ручная проверка в браузере
- Если скрипт → запустить и проверить output
- Если только документация → N/A

### 3. Нет регрессий
- Если есть тесты → полный прогон, не только changed
- Если UI → проверить соседние страницы/компоненты
- Если хук → проверить что другие хуки не сломались
- Quick check: `git diff` — нет ли случайных изменений в других файлах

### 4. Документация
- SESSION.md обновлён с текущей работой
- CHANGELOG.md обновлён (если версионное изменение)
- Новые модули документированы в .claude-docs/ (если проект использует)

### 5. Знания записаны
- Были ошибки (2+ попыток)? → /learn или /retro должен быть вызван
- Были коммуникативные инсайты? → /learn communication
- Были успешные стратегии? → /learn success (опционально)
- Проверить: knowledge-log.jsonl имеет записи за эту задачу

### 6. Нет мусора
- console.log / print для дебага убраны
- TODO/FIXME/HACK в новом коде → либо убрать, либо создать issue
- Временные файлы удалены
- .env / credentials не в коммите

### 7. Коммит
- Изменения закоммичены (если задача этого требует)
- Коммит-сообщение осмысленное, не "fix"
- Нет случайных файлов в git add

## Contextual Checks

### 8. Безопасность (если auth/input/API)
- Input validation на границе системы
- Нет SQL injection, XSS, command injection
- Секреты не hardcoded
- CORS/auth правильно настроены

### 9. i18n (если мультиязычный проект)
- Новые строки в файлах перевода
- Нет hardcoded текстов в UI
- RTL если применимо

### 10. a11y (если UI)
- Semantic HTML
- Keyboard navigation
- Screen reader labels

### 11. Performance (если тяжёлые операции)
- Нет N+1 запросов
- Большие списки paginated
- Нет блокирующих операций в UI thread

### 12. Spec-артефакты (если задача велась через /decompose с артефактами)

Применимо, когда у задачи есть `.claude-docs/specs/<дата>-<slug>/` (декомпозиция 8+ шагов).

**Механическая проверка маркеров** (выполнить команду, не оценивать на глаз):
```bash
grep -rn "NEEDS CLARIFICATION" <корень проекта>/.claude-docs/specs/<папка задачи>/
```
- Найден хотя бы один маркер → **FAIL**. Задача выполнялась на незакрытой ассумпции —
  это отказ clarify-гейта, а не мелочь. Исправление: задать вопрос пользователю,
  вписать ответ в spec.md, регенерировать plan/tasks если ответ меняет план.

**Gates и Complexity Tracking:**
- В plan.md есть непройденный gate-чекбокс БЕЗ строки в Complexity Tracking → CONCERNS
  (нарушен протокол документирования отступлений).

**Синхронность артефактов:**
- tasks.md содержит задачи не в статусе done при объявлении «готово» → проверяется
  через DoD (check 1); рассинхрон plan.md ↔ tasks.md (шаги есть, задач нет) → CONCERNS.

## Вес проверок

| Проверка | Вес при FAIL |
|----------|-------------|
| DoD, Код работает, Нет регрессий | Блокер → FAIL |
| Документация, Знания | Minor → CONCERNS |
| Мусор, Коммит | Minor → CONCERNS |
| Безопасность | Блокер → FAIL |
| i18n, a11y, Performance | Context-dependent |
| Spec-артефакты: открытые [NEEDS CLARIFICATION] | Блокер → FAIL |
| Spec-артефакты: gates без Complexity Tracking, рассинхрон | Minor → CONCERNS |
