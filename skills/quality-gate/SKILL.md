# Quality Gate — Pre-Done Verification

**Type:** worker

Гейт между "сделано" и "готово". Не позволяет объявить задачу завершённой без проверки.

**MANDATORY READ:** Load `references/checks.md` — полный список проверок.

## Зачем

| Без гейта | С гейтом |
|-----------|----------|
| "Готово" = субъективное ощущение | "Готово" = объективные критерии пройдены |
| Забытые тесты, незаписанные знания | Чеклист не пропускает |
| Качество зависит от усталости/спешки | Качество стабильно |

## Step 1: Определить scope

Что проверяем:
- Если передано имя скилла → проверить его DoD
- Если передано описание задачи → проверить по universal checklist
- Если ничего → проверить текущую задачу в контексте

## Step 2: Собрать evidence

### Universal Checklist

| # | Проверка | Как |
|---|---------|-----|
| 1 | **DoD выполнен** | Если есть DoD (скилл, план) — все чекбоксы ✅ |
| 2 | **Код работает** | Тесты проходят / Playwright verify / ручная проверка |
| 3 | **Нет регрессий** | Другие функции не сломаны |
| 4 | **Документация** | SESSION.md обновлён, CHANGELOG если нужно |
| 5 | **Знания записаны** | Были ошибки/инсайты? → /learn или /retro вызван |
| 6 | **Нет мусора** | Debug-код, console.log, TODO-хаки убраны |
| 7 | **Коммит** | Изменения закоммичены (если требуется) |

### Contextual Checks (не всегда применимы)

| # | Проверка | Когда |
|---|---------|------|
| 8 | **Безопасность** | Если затронуты auth, input, API |
| 9 | **i18n** | Если проект мультиязычный |
| 10 | **a11y** | Если UI изменения |
| 11 | **Performance** | Если тяжёлые операции |
| 12 | **Spec-артефакты** | Если задача велась через /decompose 8+ (есть `.claude-docs/specs/<задача>/`): grep по `[NEEDS CLARIFICATION]` — найден → FAIL; gates без Complexity Tracking → CONCERNS |

## Step 3: Вердикт

| Вердикт | Условие | Действие |
|---------|---------|----------|
| ✅ **PASS** | Все universal checks пройдены | Задача готова |
| ⚠️ **CONCERNS** | 1-2 minor issues, не блокеры | Готова, но отметить issues |
| ❌ **FAIL** | Блокирующие проблемы | Не готова, список что исправить |
| 🔓 **WAIVED** | Пользователь осознанно пропускает | Готова, причина записана |

## Step 4: Отчёт

```
🚦 QUALITY GATE — [задача]
━━━━━━━━━━━━━━━━━━━━━━━━

[✅ PASS | ⚠️ CONCERNS | ❌ FAIL | 🔓 WAIVED]

Проверки:
✅ DoD выполнен
✅ Код работает  
✅ Нет регрессий
⚠️ SESSION.md не обновлён
✅ Знания записаны
✅ Нет мусора
❌ Не закоммичено

[Если FAIL: что исправить]
[Если CONCERNS: что отметить]
[Если WAIVED: причина]
```

## Step 5: Запись результата

Записать в knowledge-log.jsonl:
```json
{"ts":"ISO","worker":"quality-gate","type":"gate","output":{"status":"pass|concerns|fail|waived","checks_passed":N,"checks_total":M,"issues":[]}}
```

## Rules

- Не пропускать universal checks — они минимальны
- WAIVED только по явному решению пользователя, не по умолчанию
- При FAIL — не блокировать работу, а показать что исправить
- Contextual checks применять ТОЛЬКО когда релевантны
- Гейт не заменяет review — он дополняет
- Если пользователь торопится — CONCERNS лучше чем молчание

## Definition of Done

- [ ] Scope определён
- [ ] Universal checklist пройден
- [ ] Contextual checks применены (если релевантны)
- [ ] Вердикт вынесен
- [ ] Отчёт показан пользователю
- [ ] Результат записан в knowledge-log.jsonl
