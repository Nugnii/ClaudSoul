# Pipeline — L1 Task Orchestrator

**Type:** orchestrator

Полный цикл выполнения задачи от запроса до проверенного результата. Связывает /decompose, execution и /quality-gate в единый поток.

## Зачем

| Без пайплайна | С пайплайном |
|---------------|-------------|
| Забыл декомпозировать → застрял | Decompose-first автоматически |
| Сделал → забыл проверить | Quality gate обязателен |
| Нет понимания текущей фазы | Фаза явная: scope/plan/execute/verify/done |
| Пропущены знания, не обновлён SESSION.md | Гейт не пропустит |

## Фазы

```
📋 SCOPE → 🗂️ PLAN → ⚙️ EXECUTE → 🚦 VERIFY → ✅ DONE
```

Каждая фаза имеет чёткий вход и выход. Переход — только при выполнении условия.

## Phase 1: SCOPE — определить границы

### Вход
- Описание задачи от пользователя (или аргумент скилла)

### Действия
1. Переформулировать задачу (Пункт 0 из CLAUDE.md)
2. Определить что входит / не входит
3. Определить критерии успеха

### Выход
```
📋 SCOPE
━━━━━━━
Задача: [переформулировка]
Входит: [список]
НЕ входит: [список]
Успех: [критерии]
```

### Условие перехода
- Scope подтверждён пользователем (для 8+ шагов)
- Scope показан (для 4-7 шагов)
- Для 1-3 шагов — Phase 2 пропускается, сразу в Phase 3

## Phase 2: PLAN — декомпозиция

### Вход
- Подтверждённый scope из Phase 1

### Действия
1. Вызвать /decompose с описанием задачи
2. Получить план: шаги, зависимости, milestones, параллелизм
3. Создать tasks (TaskCreate) по плану

### Выход
- План от /decompose
- Tasks созданы

### Условие перехода
- План показан пользователю
- Для 8+ шагов — план подтверждён
- Tasks созданы

### Пропуск
- Задача ≤ 3 шагов → Phase 2 пропускается, scope = план

## Phase 3: EXECUTE — выполнение

### Вход
- План (из Phase 2 или scope из Phase 1 для простых задач)
- Tasks (если созданы)

### Действия
1. Выполнять шаги по плану
2. Параллельные шаги — выполнять параллельно (Agent tool)
3. Каждый завершённый шаг → отметить task done
4. При блокере → остановиться, показать пользователю, дождаться решения

### Правила execution
- Один шаг = один проверяемый результат
- Не расширять scope без явного решения
- Если обнаружен новый шаг — добавить явно, сообщить пользователю
- При ошибке — следовать протоколу из CLAUDE.md (reproduce → analyze → plan → fix)
- После 2+ попыток починить ошибку → /learn автоматически

### Выход
- Все шаги выполнены (или блокер эскалирован)

### Условие перехода
- Все tasks отмечены done
- Нет незакоммиченных изменений (если задача требует коммитов)

## Phase 4: VERIFY — проверка качества

### Вход
- Выполненная задача из Phase 3

### Действия
1. Вызвать /quality-gate с описанием задачи
2. Получить вердикт: PASS / CONCERNS / FAIL / WAIVED

### Обработка вердикта

| Вердикт | Действие |
|---------|----------|
| ✅ PASS | → Phase 5 (DONE) |
| ⚠️ CONCERNS | → Phase 5 (DONE), issues отмечены |
| ❌ FAIL | → вернуться в Phase 3, исправить что указано |
| 🔓 WAIVED | → Phase 5 (DONE), причина записана |

### Цикл FAIL → FIX
- При FAIL — показать что исправить
- Вернуться в Phase 3 для исправления только указанных issues
- Повторить Phase 4
- Максимум 3 цикла FAIL → FIX. Если после 3-го всё ещё FAIL — эскалировать пользователю

## Phase 5: DONE — завершение

### Действия
1. Показать итоговый отчёт
2. Обновить SESSION.md
3. Если были ошибки/инсайты — предложить /learn или /retro

### Итоговый отчёт

```
✅ PIPELINE COMPLETE — [задача]
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Фаз: 5 | Шагов: N | Время: ~X мин
Quality: [PASS|CONCERNS|WAIVED]

Результаты:
- [артефакт 1]
- [артефакт 2]

[Если CONCERNS: ⚠️ issues]
[Если были /learn: 📝 записано N знаний]
```

## Адаптивность — не все задачи одинаковы

### Простые задачи (1-3 шага)
```
SCOPE → EXECUTE → VERIFY → DONE
```
Без декомпозиции. Quick scope, сразу делать, гейт в конце.

### Средние задачи (4-7 шагов)
```
SCOPE → PLAN (light) → EXECUTE → VERIFY → DONE
```
Лёгкий план (список шагов), execution, гейт.

### Сложные задачи (8+ шагов)
```
SCOPE → PLAN (full) → EXECUTE → VERIFY → DONE
```
Полная декомпозиция с milestones. Подтверждение плана. Гейт на каждом milestone (опционально).

### Milestone-гейты (для 8+ шагов)
После каждого milestone — мини-гейт:
- Код компилируется / работает?
- Нет регрессий?
- Можно коммитить?

Если мини-гейт не пройден — исправить до перехода к следующему milestone.

## Checkpoint

Pipeline записывает checkpoint для возможности resume:

```json
{
  "coordinator": "pipeline",
  "phase": "execute",
  "task": "описание задачи",
  "started_at": "ISO",
  "updated_at": "ISO",
  "steps_completed": [1, 2, 3],
  "steps_pending": [4, 5],
  "current_milestone": 1,
  "quality_attempts": 0
}
```

При resume — knowledge-activator покажет незавершённую операцию.

## Rules

- Pipeline не заменяет мышление — это каркас для последовательности
- Scope фиксирован. Расширение = новый pipeline или явное решение
- Quality gate обязателен. Нельзя пропустить Phase 4 (но можно WAIVE)
- FAIL → FIX максимум 3 раза. Потом — эскалация
- Для простых задач пайплайн должен быть НЕВИДИМЫМ — не показывать фазы, просто делать
- Для сложных — фазы явные, прогресс виден
- Milestone-гейты опциональны (по решению пользователя или при 10+ шагах)
- SESSION.md обновляется в Phase 5, не в каждой фазе

## Definition of Done

- [ ] Phase 1: Scope определён и подтверждён
- [ ] Phase 2: План создан (если задача > 3 шагов)
- [ ] Phase 3: Все шаги выполнены
- [ ] Phase 4: Quality gate пройден (PASS, CONCERNS или WAIVED)
- [ ] Phase 5: Отчёт показан, SESSION.md обновлён
- [ ] Знания записаны (если были ошибки/инсайты)
