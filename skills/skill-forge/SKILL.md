# Skill Forge — Исследование и создание скиллов

**Type:** worker

Когда для задачи нет подходящего скилла — исследовать проблему, найти решения, собрать скилл, применить.

**MANDATORY READ:** Load `references/complexity-gate.md` — критерии сложности и порог запуска.
**MANDATORY READ:** Load `docs/skill-contract.md` — контракт SKILL.md.

## Step 0: Complexity Gate

Оценить задачу — стоит ли создавать скилл или проще решить напрямую.

| Критерий | Порог |
|----------|-------|
| Шагов для решения | ≥ 5 |
| Повторяемость | Задача может встретиться снова |
| Доменная экспертиза | Нужны знания за пределами текущего контекста |
| Существующие скиллы | Ни один не покрывает > 50% задачи |

**Если < 2 критериев выполнено** — решить задачу напрямую, не создавать скилл.
**Если ≥ 2** — продолжить.

Показать пользователю оценку:
```
⚙️ COMPLEXITY GATE
Задача: [одна строка]
Шаги: ~N | Повторяемость: да/нет | Экспертиза: нужна/нет | Скиллы: нет подходящих
→ [FORGE] / [SOLVE DIRECTLY]
```

## Step 1: Декомпозиция задачи

Разложить задачу на составляющие:
1. **Что нужно сделать** — конкретный результат
2. **Какие знания нужны** — домены, технологии, подходы
3. **Какие инструменты нужны** — CLI, API, библиотеки
4. **Какие ограничения** — время, ресурсы, совместимость

## Step 2: Исследование проблемы

Широкий ресёрч проблемного домена:
1. **Поиск подходов** — какие методы решения существуют (веб-поиск)
2. **Best practices** — как эту задачу решают профессионалы
3. **Подводные камни** — типичные ошибки, edge cases
4. **Связь с базой знаний** — есть ли в `~/.claude/global-lessons/` релевантные уроки

Результат: список из 2-4 подходов с pros/cons.

## Step 3: Ресёрч GitHub

Поиск готовых реализаций. Для каждого подхода из Step 2:

1. **Поиск репозиториев** — GitHub Search: ключевые слова, фильтр stars > 100
2. **Оценка кандидатов** — для каждого:

| Критерий | Проверить |
|----------|-----------|
| Stars | > 100 (минимум), > 1000 (предпочтительно) |
| Последний коммит | < 6 месяцев |
| Лицензия | MIT / Apache / BSD (совместимость) |
| README | Понятно что делает и как использовать |
| Issues/PRs | Активное сообщество |

3. **Извлечение** — что можно взять:
   - Подход / алгоритм / паттерн (не код целиком)
   - Конфигурация / best practices
   - Интеграционные паттерны

Результат: таблица кандидатов.

```
📦 GITHUB RESEARCH
| Repo | ⭐ | Что даёт | Применимость |
|------|----|----------|-------------|
| ... | ... | ... | высокая/средняя/низкая |
```

## Step 4: Синтез

На основе исследования (Step 2) и ресёрча (Step 3):

1. **Выбрать подход** — какой метод решения использовать
2. **Спроектировать скилл:**
   - Определить шаги (Step 1...N)
   - Определить входы/выходы
   - Определить Definition of Done
   - Определить references (если нужны вспомогательные файлы)
3. **Учесть skill contract** — YAML frontmatter, Type: worker, DoD, Version

## Step 5: Создание скилла

Определить режим хранения:

| Инициатор | Путь | Причина |
|-----------|------|---------|
| Агент (сам решил) | `~/.claude/agent-skills/[name]/` | Песочница — не засоряет глобальное пространство |
| Пользователь (попросил) | `~/.claude/commands/[name]/` | Глобальный — доступен через /name |

Написать SKILL.md по контракту. Если нужны reference-файлы — создать в `references/`.

При agent-initiated:
- Скилл сохраняется в `~/.claude/agent-skills/`
- Лог создания записывается в `~/.claude/agent-skills/_registry.md`
- Если скилл используется 3+ раз → предложить промоушен в глобальные

## Step 6: Применение

1. Решить исходную задачу используя созданный скилл
2. Если решение успешно — скилл сохраняется
3. Если решение неудачно — скилл помечается как draft, записывается что не сработало

## Step 7: Отчёт

```
🔨 SKILL FORGE
━━━━━━━━━━━━━━
Задача: [одна строка]
Исследование: [N подходов найдено, лучший: X]
GitHub: [N репо, полезных: M]
Скилл: [name] → [путь]
Результат: [задача решена / частично / не решена]

📚 Источники:
- [подход/репо 1]
- [подход/репо 2]
```

## Rules

- НЕ создавать скилл для тривиальных задач — Complexity Gate обязателен
- НЕ копировать код из репозиториев — извлекать подходы, паттерны, конфигурации
- Исследование ШИРЕ чем GitHub — сначала понять проблему, потом искать реализации
- Agent-skills — песочница. Не засорять `~/.claude/commands/` автоматически
- Промоушен agent-skill → global: только по предложению пользователю (3+ использований)
- При ресёрче GitHub — не увлекаться количеством. 3-5 релевантных лучше 20 случайных
- Скилл создаётся ПОД задачу, не "на все случаи жизни" — YAGNI

## Definition of Done

- [ ] Complexity Gate пройден (≥ 2 критерия)
- [ ] Проблема исследована (2+ подхода)
- [ ] GitHub просмотрен (если применимо)
- [ ] Скилл создан по skill contract
- [ ] Скилл сохранён в правильное место (agent-skills / commands)
- [ ] Исходная задача решена
- [ ] Отчёт показан пользователю
