# Область доставки инструментов `scripts/`

> Ответ на вопрос «какой инструмент можно поставить в чужой проект, а какой нельзя».
> Решение о неучастии `scripts/` в установке — ADR-018. Пункт долга — D348.
> Документ состояния: описывает, как есть сейчас. Хроника — в CHANGELOG.

## Зачем этот документ

7 сентября 2026 глобальный Stop-хук звал `$ROOT/scripts/defect-class-carriers.py`, где `ROOT` —
корень ТЕКУЩЕГО проекта. В чужом проекте файла нет, код 2, печать отказа на Stop, восемь
пустых ходов подряд. Разбор показал, что вопрос «доставлять ли `scripts/`» не имеет одного
ответа: **часть инструментов доставить нельзя не потому, что они упадут, а потому, что они
НЕ упадут** — напечатают правдоподобные числа о дереве, для которого не калиброваны. Это
хуже цикла: цикл видно.

Пока классификации не было, всякая доставка означала разослать по проектам приборы с
неизвестной областью годности. Ниже — ответ по каждому, с адресом улики.

## Критерий

Инструмент **универсален**, если его предмет существует вне дерева ClaudSoul и он не читает
ни одного файла, который есть только здесь. Инструмент **только для ClaudSoul**, если верно
хотя бы одно:

* читает файл, которого в чужом проекте нет (`BACKLOG.md` этого формата, `knowledge/META.md`,
  `scripts/*.tsv`-реестры, `hooks/*.sh` как источник данных);
* его признаки **откалиброваны на этом дереве**, и точность измерена здесь же;
* решение о его области уже принято отдельно и записано.

Третий столбец отвечает на вопрос «что случится, если всё-таки доставить» — и он важнее
вердикта: молчаливый отказ и правдоподобное неверное число суть разные беды.

## Таблица

| Инструмент | Вердикт | Улика и что будет при доставке |
|---|---|---|
| `usage-outcome-audit.py` | **универсален** | Единственный якорь — `~/.claude/usage-data` (`:45`), то есть каталог машины, а не дерева. Шапка объявляет его «взглядом стороны, не знающей про ClaudSoul». Доставка ничего не меняет: он и так смотрит на машину целиком. |
| `ci-status.sh` | **универсален** | Предмет — прогон CI для ЭТОГО коммита в ЭТОМ репозитории (`gh run` по sha). Работает в любом git-репозитории с GitHub Actions. Единственная связь с деревом — `root-cause-lib.sh` для записи повода разбора, и у неё есть откат на установленную копию (`:82`), то есть на контур, который доставляется. |
| `defect-class-carriers.py` | **только ClaudSoul** | `ROOT = Path(__file__).resolve().parents[1]` (`:33`); признаки родов перечисляют носителей ЭТОГО дерева поимённо, регекспы бьют по `global-lessons\|knowledge/\|frontmatter` (`:107`), и **точность каждого рода измерена здесь** (шапка, «признак с непроверенной точностью здесь не заводится»). | `backlog-archive.sh` | **только ClaudSoul** | Работает над `BACKLOG.md` этого формата (☑/☐/⊘, «Проверка», «Вердикт»). Решение уже записано отдельно: «Убирается ТОЛЬКО долг ClaudSoul… свой формат и свой владелец» (`hooks/session-collector.sh:551-537`). |
| `backlog-refresh-readings.sh` | **только ClaudSoul** | `BACKLOG="${BACKLOG_FILE:-$REPO/BACKLOG.md}"` (`:68`), исполняет «Показания» пунктов — произвольные команды из файла этого формата. То же решение, что у архиватора. |
| `backlog-recheck.sh` | **только ClaudSoul** | Падает без `$REPO/BACKLOG.md` (`:36`), читает `knowledge/META.md` (`:123`) и `hooks/lib/link_symmetry.py` (`:93`). Предмет — «остался ли закрытый пункт закрытым», и он о долге ClaudSoul. |
| `sync-drifted.sh` | **только ClaudSoul** | Чинит расхождение между ЭТИМ репозиторием и `~/.claude`; признак берёт у `$REPO/hooks/tests/drift-check.sh` (`:34`), приёмники выводит из `install.sh` (`:144`). В чужом проекте предмета не существует. |

| `docs-refresh-claims.sh` | **только ClaudSoul** | Реестр утверждений — `scripts/doc-claims.tsv` (`:50`), перечисляющий числа документов ЭТОГО проекта. |
| `measurement-due.sh` | **только ClaudSoul** *(параметризуем)* | Реестр — `scripts/measurements.tsv` (`:31`), и он подменяем переменной `MEASUREMENT_REGISTRY`. Механика периодов универсальна, СОДЕРЖИМОЕ реестра — нет: команды в нём про это дерево. Годен к доставке только вместе со своим реестром для чужого проекта, а такого реестра не существует. |
| `dep-index.py` | **только ClaudSoul** *(параметризуем)* | Корень берётся из `CLAUDSOUL_REPO` либо от `__file__` (`:38`), но исключения зашиты под этот проект: `^knowledge/`, `BACKLOG`, `CHANGELOG-archive`, `SESSION` (`:48`), и разбор путей учитывает не-ASCII имена скиллов (`:62`). Механика индекса универсальна, НАСТРОЙКА — нет. |

**Итого: универсальны 2 из 11.** Оба при этом не нуждаются в доставке: `usage-outcome-audit.py`
смотрит на машину целиком, `ci-status.sh` вызывается из репозитория, где живёт CI.

## Что из этого следует

1. **Полоса доставки `scripts/` не нужна.** Ни один из одиннадцати не выигрывает от
   копирования в чужой проект: девять там неприменимы, двое и без того достают свой предмет.
   Это и есть ответ на исходный вопрос владельца «как проекту подхватить новое»: подхватывать
   нечего, а инцидент чинится адресацией (ADR-018).
2. **Два «параметризуемых» — не отложенные универсалы, а честная середина.** У обоих
   универсальна МЕХАНИКА и специфична НАСТРОЙКА. Если когда-нибудь понадобится индекс
   зависимостей или реестр замеров для чужого проекта, работа будет не «скопировать», а
   «вынести настройку наружу», и это отдельная задача с собственной ценой.
3. **Критерий важнее таблицы.** Появится двенадцатый инструмент — вердикт выводится из трёх
   строк критерия выше, а не из подражания соседям.

## Названный предел

Вердикт «универсален» проверен ЧТЕНИЕМ, а не прогоном в чужом проекте: ни один из
инструментов не запускался вне дерева ClaudSoul в рамках этой классификации. Для двух
универсальных цена ошибки мала (оба read-only), для девяти остальных вердикт «нельзя»
безопасен по построению. **Условие снятия:** если какой-то инструмент решат доставлять,
его вердикт подтверждается прогоном в чужом проекте, а не этой таблицей.
