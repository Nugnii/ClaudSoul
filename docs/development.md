## Гочи проекта (Claude их не угадает)

- **Среда исполнения Bash-инструмента — zsh, не bash.** Не полагаться на bash-семантику
  в inline-командах; парсинг — `jq`/`awk`; сложное — писать в файл (`pattern-shell-portability`).
- **Вынос sourced-под-библиотеки** (`*-lib.sh`, подключаемой через `${BASH_SOURCE[0]%/*}`):
  `install.sh` копирует все `hooks/*.sh` сам, НО фиксированные списки
  (`backfill-replay-one.sh`) и симлинк-фикстуры тестов дополнять **вручную** — иначе
  тихая поломка в изолированном окружении (`case-2026-06-20-hook-dependency-install-drift`).
- **Монолит без своего теста** → сперва характеризующий тест (сквозной прогон,
  детерминизм через фикс. session-id), потом разрез. Резать готовые функции; встроенную
  оркестрацию (мутирует глобальные, побочные эффекты) — не выносить.
- **Числа/статусы/seed — НЕ править руками** (см. таблицу механизмов ниже).
- **Перед задачей** — `mcp__claudsoul__search_knowledge` по ключевым словам
  (семантический поиск находит то, что keyword-активатор пропускает —
  `case-2026-04-16-ignored-own-knowledge-base`).

## Инструмент без объявленного результата — не инструмент

Поправка владельца 28 августа 2026, дословно: «всегда должен быть результат и проверка его
наличия при построении инструмента. Измеряемый и достижимый результат. Измерять ради
измерения это фигня. Замечать и не исправлять — фигня».

**Обязательное перед постройкой — две строки в шапке файла:**

```
# Результат: <СОСТОЯНИЕ МИРА, которое считается достигнутым>
# Проверка результата: <команда, дающая 0 при достижении>
```

**Результат — это состояние мира, а не работа прибора.** «Назвал продюсеров без отсева» —
работа. «Продюсеров без отсева ноль» — результат. Разница не стилистическая: при первой
формулировке перечисление засчитывается как завершённая работа, и находка остаётся жить.

**Если результат честно звучит как «будет видно число»** — перед тобой прибор, а не
инструмент. Тогда обязательно назвать: какое РЕШЕНИЕ это число изменит, у кого и к какому
сроку. Прибор без такого предложения — измерение ради измерения.

**Находка инструмента, оставленная без починки,** обосновывается ЧИСЛОМ (цена, риск,
объём), а не словом «отдельная задача», и получает условие возврата, проверяемое командой
(`scripts/backlog-return-check.sh`).

**Повод конкретный и свой.** За одну сессию 27–28 августа построено семь вещей: две решают
(отказ у знания через `enforcement: deny`, отказ у гейта разбора), пять считают. Из пяти
`producer-filter-check` нашёл пять хуков без отсева чужой речи и **ничего не починил** —
это было названо «отдельным разменом» и закрыто. Цепочка до корня: результатом инструмента
объявлялось ОБНАРУЖЕНИЕ, а не УСТРАНЕНИЕ, поэтому перечисление засчиталось как работа.

**Правило держится стражем, а не текстом:** `hooks/tests/test_instrument_contract.sh`
краснеет, если инструмент в корне `scripts/` не несёт обеих строк (подкаталоги, в том числе
`scripts/ablation/`, страж не обходит). Замер на 28 августа 2026 до
введения: инструментов 28, с объявленным результатом — 0.

## Находка по ходу работы не расширяет текущую задачу

Обнаружил дефект, пока делаешь другое — **строка в `BACKLOG.md` с идентификатором**, а не
починка по дороге.

Причина конкретная. За одну сессию накопилось 30 незакрытых пунктов, и при сборке списка
выяснилось: большинство были **названы вслух в тот же момент, когда пропущены**. Не «не
заметил» — заметил, произнёс, пошёл дальше. Разбор шёл вглубь: брали дыру, чинили, находили
ещё несколько, чинили одну из них, и так рекурсивно. Раздел «Ограничения» в CHANGELOG работал
как способ закрыть тему, а не как долг.

Правила:

- Находка → `BACKLOG.md`, номер, чем подтверждена (число/файл), почему пропущена.
- Задача закрывается по **своему** критерию. «Частично сделано» не существует: либо критерий
  выполнен, либо пункт возвращается в бэклог.
- **Откладывание без условия возврата запрещено.** Пункт, требующий накопления данных,
  получает проверяемое условие (`n ≥ 20 наблюдений`, `≥ 30 срабатываний`, `первая запись
  такого-то типа`). Без условия — только закрытие или явный отказ (`⊘ waived` с причиной).
- Условия проверяет `metrics-collector.sh`: когда выполнено, пункт поднимается в отчёт сам.

## Проверять на чужой машине, а не только на своей

Тесты, зелёные у разработчика, ничего не говорят о проекте: часть хуков берёт библиотеки из
установленного `~/.claude/hooks/`, а команды `date -j`, `stat -f`, `tail -r` и свёртка регистра
через `tr` работают ровно на одной системе. За одну сессию это дало пять независимых причин
падения CI, и ни одну нельзя было увидеть локальным прогоном.

Механизм — работа `Hook tests (bash)` в CI: ubuntu-latest, ClaudSoul не установлен, из
инструментов только `jq`. Локальное воспроизведение той же рамки:

```bash
docker run --rm -v "$PWD":/repo:ro -w /repo debian:stable-slim bash -c '
  apt-get update -qq && apt-get install -y -qq jq git python3
  cp -R /repo /work; cd /work/hooks/tests && bash run_all.sh'
```

Монтирование только для чтения и копия в `/work` обязательны: продукт из контейнера не меняется.

Правила, выведенные из этих пяти причин:

- **Свёртка регистра для кириллицы — только `to_lower` из `portable-lib.sh`.** GNU `tr` кириллицу
  не сворачивает ни в какой локали. Проверяет `test_case_folding_portable.sh`.
- **Время и файлы — `iso_epoch` / `file_mtime`**, обратный порядок строк — `reverse_lines`.
- **Библиотека ищется сначала рядом с собой, потом в установленном каталоге.** Обратный порядок
  выключает хук на чистой машине молча.
- **Классы символов с кириллицей в регулярных выражениях запрещены:** GNU grep в локали `C.UTF-8`
  отвергает диапазон `[а-яё]` с ошибкой «Invalid collation character». Границу слова делать
  нормализацией пробелов и точным поиском подстроки.
- **Внешние команды вне POSIX-минимума проверять на наличие.** `file(1)` нет в минимальных
  образах, и `file "$f" | grep -q text || continue` тихо пропускал все файлы.

## Обязательные шаги при добавлении

- **Хук** → тест в `hooks/tests/` + регистрация в `install.sh` (`HOOKS_CONFIG`) + если
  source-ит под-библиотеку, см. гочу выше + синхронизировать число
  (`count-stats.sh --patch-claude-md`).
- **Фича с режимом или обязанностью для ВЛАДЕЛЬЦА** → механизм видимости, не текст:
  маркер состояния + сигнал сессии + страж действий — так же, как правила агента
  получают активатор/blocker. Вопрос при сдаче: «есть ли здесь что-то, что владелец
  должен помнить? где механизм, снимающий это с его памяти?» (урок ablation-фазы
  2026-08-08: §6 прошёл три раунда рецензии текстом, дыру вскрыл вопрос владельца).
- **Тест стража** → хелперы `assert_*` копировать из соседнего теста, не изобретать:
  прувер `test_guards_provable.sh` распознаёт доказательства по сигнатурам
  (`SILENT_PATTERNS`) — ручной `if [ -z … ]` он доказательством тишины не считает
  (поймано на test_timestamp_inject, три правки подряд 2026-08-08).
- **Скилл** → контракт `docs/skill-contract.md`; таблицы в README авто-генерируются
  (`scripts/regen-readme-skills.sh`), не править руками.
- **Знание** → формат по `knowledge/META.md` (единственный источник спецификации); универсальные — в seed через `regen-seed.py`.

## Журналы

- Каждое изменение → `CHANGELOG.md`; каждая сессия → `SESSION.md`; архитектурные
  решения → `docs/decisions.md` (ADR).
