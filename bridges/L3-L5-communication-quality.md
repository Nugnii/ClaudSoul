# Мост L3↔L5: Мониторинг качества коммуникации

> Навык: наблюдать за тем, КАК общаешься, и корректировать подход.

## Зачем

Без этого моста система может общаться плохо и не знать об этом. Коррекции от собеседника ("не так", "короче", "ты не понял") — это мета-сигналы о качестве коммуникации, но они обрабатываются только как content (L3), не как метрика (L5).

**Ценность:** Системное снижение количества коррекций. Не "запомнить этот конкретный случай", а "понять, что я систематически делаю не так в коммуникации".

## Цикл

```

┌──────────────┐            ┌──────────────┐            ┌──────────────┐
│ Коррекции,   │──метрики─→ │ Анализ:      │──правило→  │ Изменённый   │
│ satisfaction  │            │ "60% коррек- │            │ стиль        │
│ signals      │            │ ций = 'слиш- │            │ коммуникации │
│              │            │ ком длинно'" │            │              │
└──────────────┘            └──────────────┘            └──────────────┘
       ↑                                                       │
       └────────── наблюдение: коррекций стало меньше ─────────┘
```

## Что даёт

| Без моста | С мостом |
|-----------|----------|
| Каждая коррекция = отдельный случай | Паттерн коррекций → системное улучшение |
| "Этот раз был многословным" | "Я систематически многословен в контексте X" |
| Реакция на фидбэк | Превентивная адаптация стиля |

## Метрики (для metrics-collector)

- `corrections_per_session` — количество коррекций от собеседника за сессию
- `correction_types` — категоризация: too_verbose, wrong_interpretation, missed_signal, wrong_action
- `response_acceptance_rate` — доля ответов, принятых без коррекции
- `trend` — corrections_per_session за последние 5 сессий (растёт/падает?)

## Реализация

1. **В session-collector:** при Stop — подсчитать коррекции (ищем паттерны: "нет", "не так", "я имел в виду", "стоп", "ОШИБКА")
2. **В metrics-collector:** агрегация corrections по сессиям, trend analysis
3. **В knowledge-activator:** если trend растёт → инжектировать "⚠️ Коммуникация деградирует: [тип коррекций]"
4. **В /learn:** communication case с correction_type → позволяет строить паттерны коммуникативных ошибок
