# Мост L3↔L6: Коммуникативное предсказание

> Навык: выбор формулировки под ожидаемую реакцию собеседника.

## Цикл

```
L3 (Communication)          L6 (Prediction)            L3 (Communication)
┌──────────────┐            ┌──────────────┐           ┌──────────────┐
│ Модель       │──данные──→ │ Гипотеза:    │──выбор──→ │ Наблюдение   │
│ собеседника  │            │ "если X → Y" │  подачи   │ реакции      │
└──────────────┘            └──────────────┘           └──────────────┘
       ↑                                                      │
       └───────────── обновление модели ──────────────────────┘
```

## Данные L3 → L6

Модель собеседника (из user_profile.md и наблюдений сессии):
- **Стиль** — лаконичность vs детальность, тон, темп
- **Ценности** — что важно (точность, скорость, контроль, свобода)
- **Паттерны** — как корректирует, что игнорирует, что хвалит
- **Состояние** — текущее (усталость, энтузиазм, нетерпение)

## Предсказание L6

На основе модели, перед каждой формулировкой:
1. **Оценить варианты подачи** — краткий vs детальный, вопрос vs утверждение, один вариант vs несколько
2. **Предсказать реакцию** — на каждый вариант, по модели собеседника
3. **Выбрать оптимальный** — максимизирующий вероятность нужной реакции
4. **Записать предсказание** (implicit) — для верификации

## Верификация L3

После реакции собеседника:
- **Совпадение** → reinforce паттерн в модели
- **Отклонение** → обновить модель (что не учёл?)
- **Коррекция** → записать через /learn (communication case)

## Правила применения

### Когда активировать
- При любом ответе собеседнику (implicit)
- Усиленно — при выборе между вариантами подачи
- Максимально — при потенциально конфликтных/корректирующих формулировках

### Три уровня (по аналогии с Prediction)
1. **Implicit** — всегда: подстройка стиля без объявления
2. **Gentle** — при confidence 3+: "Предлагаю [вариант]. Это направление?"
3. **Proactive** — при confidence 4+ и low cost: формулировать оптимально без спроса

### Ограничения
- Модель собеседника — гипотеза, не факт (принцип неопределённости)
- Confidence модели ≤ 2 для нового собеседника
- Предсказание реакции ≠ манипуляция. Цель: эффективная коммуникация, не влияние

## Психологические основания

| Концепция | Как используется |
|-----------|------------------|
| Theory of Mind | Моделирование ментального состояния |
| Framing effect | Одна информация, разная подача → разная реакция |
| Communication Accommodation | Подстройка стиля под собеседника |
| Речевые акты (Austin, Searle) | Вопрос может быть утверждением, предложение — давлением |

## Связь с существующими механизмами

- **Prediction (L6)** — предсказывает тему; этот мост предсказывает реакцию
- **Interlocutor model auto-update (v0.2.7)** — session-collector обновляет модель; этот мост использует её в реальном времени
- **Satisfaction signals (L3)** — данные для этого моста; мост делает их actionable

## Каскадная верификация (v1.1.0)

Когда одна задача проходит через несколько коммуникативных циклов (переформулировка → уточнение → предложение → коррекция → повторная переформулировка), каждый цикл — отдельная активация этого моста. Без фиксации каждого звена в prediction log возникает survivorship bias: в модели собеседника остаются только первые-раундовые впечатления, и L3 не получает данных для обновления на поздних этапах задачи.

**Три типа триггеров** в каскаде (приоритет BACKWARD > FORWARD > PROPOSAL):

| Триггер | L3 → L6 данные | L6 → L3 действие |
|---------|----------------|------------------|
| **FORWARD** — агент переформулировал | Оценка стиля коммуникации собеседника | Выбор формулировки переформулировки под его ожидания |
| **PROPOSAL** — агент предложил подход | Модель decision-patterns собеседника | Подача предложения в предпочтительной форме (вопрос vs утверждение) |
| **BACKWARD** — собеседник скорректировал | Сигнал несовпадения модели с реальностью | Немедленное обновление интерпретации + пометка урока |

**Автоматизация:** хук `reformulation-tracker.sh` детектирует все три триггера в UserPromptSubmit и инжектит напоминание зафиксировать accuracy. Это делает мост не "правилом, которое агент должен помнить", а активным каналом L3↔L6 с внешним триггером.

Каскадная фиксация питает interlocutor model более плотными данными: не "собеседник принял / отверг задачу", а "на шаге 1 adjacent, на шаге 3 miss с уроком X, на шаге 4 exact" — это превращает модель собеседника из статичной в поведенческую.

## Intrusiveness cost & 4D gate (v1.3.0)

Предыдущие секции моста описывали **как формулировать** при выходе наружу. Эта секция — **выходить ли вообще и в каком режиме**. Две разные задачи на одном мосту.

### От 1D к 4D

Ранняя версия моста (v1.2) формулировала gate как надстройку над «three modes» (silent prep / gentle / proactive), которые выбирались одной осью — `confidence`. Это систематически ломало UX:

- Silent prep при высокой частоте = шум (агент «слишком умный»)
- Gentle suggestion в момент фокуса собеседника = прерывание
- Proactive action без учёта состояния = патернализм
- Высокий confidence на нерелевантном предсказании = уверенность в мусоре

В v1.3 режимы перестают быть входом gate и становятся его **выходом**. Gate — функция четырёх осей, режим выбирается downgrade-лестницей.

### Четыре оси решения

| Ось | Вопрос | Природа | Слой |
|-----|--------|---------|------|
| `confidence` | Насколько вероятно, что предсказание верно? | Эпистемическая | L6 |
| `value` | Стоит ли это внимания? `= confidence × impact × trajectory_alignment` | Семантическая | L4+L6 |
| `cost` | Какой ценой вмешаться сейчас? | Нормативная | L3 |
| `state` | Принимает ли собеседник ввод? | Прагматическая | L3 |

Gate живёт на стыке: L6 даёт `confidence` и вместе с L4 формирует `value`; L3 даёт `cost` и `state`. Все четыре оси независимы — пропуск любой из них приводит к предсказуемому классу ошибок (см. выше).

### Cost model — шесть осей

**Пять осей «cost of speaking»** (почему не говорить сейчас):

| Ось | Что измеряет | Пример высокого значения |
|-----|--------------|-------------------------|
| `timing_cost` | Состояние собеседника | Фокус на задаче, тупик требует тишины |
| `interaction_cost` | Цена переключения внимания | Длинный вдумчивый ответ, нарушение потока |
| `authority_cost` | Выглядит ли как самовольное решение | Proactive action без явного мандата |
| `redundancy_cost` | Очевидность сказанного | То, что собеседник и так знает/скажет сам |
| `surprise_cost` | Неожиданность в рамках контракта | Уходим от темы, меняем модальность |

**Шестая ось — контрвес** (почему не молчать сейчас):

| Ось | Что измеряет | Пример высокого значения |
|-----|--------------|-------------------------|
| `silence_cost` | Цена пропуска момента | Window closing / собеседник вот-вот запустит необратимое / связь видна только сейчас / систематическое молчание эрозирует доверие |

**Важно:** `silence_cost` — не «+1 к пяти». Она измеряет другую величину (регрет молчания против регрета речи). Без неё gate systematically favors silence.

### Компоненты `silence_cost`

- **Window cost** — контекст сейчас закроется, сессия уйдёт, собеседник запустит необратимое
- **Decay cost** — связь читается только в текущей конфигурации, через 3 сообщения не соберётся
- **Asymmetric impact** — пропущенное предупреждение дороже лишнего озвученного, если действие необратимо
- **Trust erosion** — накопительное молчание при видимой проблеме = потеря доверия к silent prep

### State — четыре состояния

State выводится L3 из темпа, тона, длины пауз, типов последних сообщений. State **ограничивает** допустимые режимы независимо от `confidence` / `value` / `cost`.

| State | Признаки | Допустимые режимы |
|-------|----------|-------------------|
| `focus` | длинные технические сообщения, узкий scope, быстрый темп | `silent_prep` (default); `gentle_suggestion` только при emergency |
| `idle` | паузы, мета-реплики, полуоткрытые вопросы | `gentle_suggestion`, `proactive_action` разрешены |
| `stuck` | повторяющиеся ошибки, переформулировки одной задачи, явные сигналы тупика | `proactive_action` приоритетно — `silence_cost` растёт быстро |
| `exploration` | «а что если», открытые гипотезы, смена доменов | `gentle_suggestion` — сопровождение; `proactive_action` нежелателен |

Нереализовано в v1.3: автоклассификация state по темпу и характеру сообщений. Сейчас оценивается агентом эвристически.

### Gate как сравнение сожалений

Gate — не порог, а **сравнение двух регретов** по четырём осям:

```
regret_if_speak  = cost(timing, interaction, authority, redundancy, surprise) - value
regret_if_silent = silence_cost(window, decay, asymmetric_impact, trust_erosion)

should_intervene =
    E[regret_if_silent] > E[regret_if_speak]
    AND state_allows_chosen_mode
    AND action_is_reversible_or_authorized
```

Формулировка сменяет вопрос:

> ~~Достаточно ли ценно сказать?~~
> **Что хуже: сказать зря или смолчать зря?**

`value` в формуле — не синоним `confidence`. Высокий confidence при низком value (верное предсказание мусора) → `regret_if_speak` большой, gate закрывается.

Второе условие (`state_allows_chosen_mode`) — нормативный фильтр, не выводимый из математики: бывают состояния диалога, где конкретный режим табуирован (proactive в focus), даже при очень высоком silence_cost.

Третье условие (`reversible_or_authorized`) — защита от proactive action, которое нельзя откатить.

### Budget — накопительный предохранитель

Gate работает на отдельной интервенции. Budget — на сессии целиком.

| Параметр | Поведение |
|----------|-----------|
| **Per-session cap** | N внешних интервенций на сессию (старт: N=5 для gentle, N=2 для proactive) |
| **Cost weighting** | Proactive стоит больше gentle (множитель ×2) |
| **Shrinking on ignores** | После 2+ игноров собеседника budget сжимается (−1 за каждый) |
| **Emergency override** | При `silence_cost` ≥ 4 (необратимое / закрывающееся окно) budget игнорируется |
| **Silence debt** | Подавленные высокоценные интервенции (gate passed по cost, но budget заблокировал) накапливаются; учитываются при следующей удобной возможности, но не сбрасываются батчем |

Emergency override принципиален: без него budget превращается из предохранителя в намордник. Суть override: «молчание здесь дороже любого предохранителя».

Silence debt — компенсация за false silence. Её нельзя «разрядить» одним большим сообщением (это взрыв) — только учитывать при следующем естественном окне.

### Downgrade ladder — режимы как выход gate

Gate не бинарный («говорить / молчать»), а **выбирает точку** на лестнице:

```
proactive_action  →  gentle_suggestion  →  silent_prep  →  ignore
```

Gate **по умолчанию консервативный**: начинает с `proactive_action` и опускается вниз при высоком `cost`, низком `value` или несовместимом `state`. Это предотвращает накопительную навязчивость.

| Режим | Gate применяется? | Budget применяется? |
|-------|-------------------|--------------------|
| `ignore` | N/A (gate закрыт) | Нет |
| `silent_prep` | Нет — не выходит наружу | Нет (но накопительный cost через метрики сессии) |
| `gentle_suggestion` | Да — обязательно | Да |
| `proactive_action` | Да — жёстче (нижний порог `silence_cost` выше) | Да, с множителем ×2 |

Примеры:

| confidence | value | cost | state | → режим |
|-----------|-------|------|-------|---------|
| 5 | 4 | 5 | focus | `silent_prep` (state блокирует вмешательство) |
| 3 | 4 | 1 | stuck | `proactive_action` (silence_cost растёт, value оправдан) |
| 2 | 5 | 3 | exploration | `gentle_suggestion` (молчать дороже, exploration позволяет вопрос) |
| 5 | 1 | 2 | idle | `ignore` (value≈0 — уверенность в мусоре) |

### Ключевое правило (для rules/CLAUDE.md)

> Внешний выход предсказания — функция **четырёх осей**: `confidence` (L6: эпистемическая надёжность) × `value` (L4+L6: релевантность траектории × impact) × `cost` (L3: шесть осей intrusiveness) × `state` (L3: focus / idle / stuck / exploration). Gate — сравнение сожалений: `E[regret_if_silent] > E[regret_if_speak] AND state_allows_chosen_mode AND reversible_or_authorized`. Режим (proactive / gentle / silent / ignore) — выход downgrade-лестницы, не вход.

### Психологические основания (дополнение)

| Концепция | Как используется |
|-----------|------------------|
| Regret minimization (Savage) | Gate как сравнение ожидаемых регретов, а не абсолютных ценностей |
| Loss aversion (Kahneman-Tversky) | Обоснование asymmetric_impact: пропущенное предупреждение дороже лишнего |
| Social cost of interruption (Mark et al.) | Эмпирическая база для timing/interaction/surprise cost |
| Speech acts (Searle) | Gate как проверка, имеет ли речевой акт «право на перформатив» в данном контексте |
