# Мост L3↔L7: Совместный язык

> Навык: развитие общего языка — сокращений, отсылок, неявных соглашений.

## Зачем

Когда два человека долго работают вместе, у них появляется shared vocabulary: "тот баг" (оба знают какой), "как в прошлый раз" (оба помнят). Это УСКОРЯЕТ коммуникацию и УГЛУБЛЯЕТ со-мышление. Без этого моста каждая сессия начинается с нуля — нет "общей истории".

**Ценность:** Эффективность коммуникации растёт со временем. Пара "притирается". Глубина со-мышления увеличивается, потому что меньше времени тратится на объяснения.

## Цикл

```
L3 (Communication)          L7 (Co-Cognition)           L3 (Communication)
┌──────────────┐            ┌──────────────┐            ┌──────────────┐
│ Повторяемые  │──паттерн─→ │ Совместный   │──shorthand→│ "Как с       │
│ термины,     │            │ инсайт       │            │ intensity"   │
│ отсылки      │            │ становится   │            │ (без         │
│              │            │ shorthand    │            │ пояснений)   │
└──────────────┘            └──────────────┘            └──────────────┘
       ↑                                                       │
       └──────── собеседник использует shorthand ──────────────┘
```

## Что даёт

| Без моста | С мостом |
|-----------|----------|
| Каждый раз объяснять контекст | "Как с intensity" — оба понимают |
| Формальный язык | Эволюция к shared vocabulary |
| Каждая сессия = чужие люди | Накопление общей истории |

## Реализация

1. **В interlocutor model (user_profile.md):** секция `## Shared vocabulary` — термины, отсылки, сокращения, которые собеседник использует повторно
2. **В session-collector:** при Stop — выявлять shorthand (фразы, используемые 3+ раз за сессию или кросс-сессионно без пояснения)
3. **В правилах CLAUDE.md:** если собеседник использует known shorthand — НЕ переспрашивать, применять сразу
4. **При со-мышлении:** ключевые совместные концепции автоматически становятся shorthand после 2+ использований

## Реализовано (v1.21.0, 2026-08-07)

| Элемент проекта | Где живёт |
|-----------------|-----------|
| Хранилище словаря | память проекта `memory/shared-vocabulary.md` (грузится каждую сессию через MEMORY.md) — НЕ дублируется в user_profile (канон single-source); правило «known shorthand — не переспрашивать» стоит в description самого словаря |
| Выявление shorthand на Stop (пункт 2) | `hooks/shared-language-lib.sh` → `session-collector.sh`: кандидаты «токен ×N» в Stop-алерт; тест `test_shared_language_lib.sh`, 10 случаев |
| Гейт шума | детектор работает только там, где словарь уже заведён; сигнал синтаксический (латинские/составные токены собеседника ≥ 3 раз, не в словаре), не частотно-языковой — урок v1.13.3 про придуманные словари |
| Ограничение уровня | кириллические термины не ловятся (граница слова в кириллице — отдельная задача pad_words-подхода); расширять, когда данные покажут дефицит латинских кандидатов |

Служебные «user»-сообщения (task-notification, загрузка скиллов, ide-события,
продолжение сессии) отбрасываются до токенизации — иначе детектор тонет в их латинице.
