# Правила разработки механизмов ClaudSoul

Вынесены из `rules/CLAUDE.md` 23 сентября 2026: касаются только разработки ClaudSoul и не
должны грузиться в каждый проект. Грузятся, когда читается файл под путями из шапки;
названный предел — создание нового файла БЕЗ чтения соседнего правило не подгрузит.
Условие снятия: Claude Code начнёт подгружать правила по `paths` и при записи файла.

## Hooks — alive learning system

Хуки инжектят маркеры в context. Reference table:

| Маркер | Хук | Действие |
|--------|-----|---------|
| ⚠️ 2+ провала в окне 6 | error-tracker (PreToolUse) | STOP, re-read errors, 2-3 hypotheses, после fix → `/learn` |
| 📚 Relevant knowledge | knowledge-activator (PreToolUse) | READ → следуй, outdated → `/learn` |
| 📎 Аналогии из других доменов | knowledge-activator | Evaluate механизм, blind apply нельзя; работает → `/learn` с edge similar_to |
| 📎 Кросс-контурные упоминания | knowledge-activator | Pattern ↔ entity связь, рассмотреть |
| 🛑 Blocker | blocker-tier-check (PreToolUse) | Silent — реконсидер approach, применить blocker_reminder. НЕ эхай в output |
| ⛔ ОТКАЗ … нет названного исхода | five-whys-gate (PreToolUse) | Страж говорит только отказом на записи; без права на отказ — молчит (D1105, D1151). Сперва — где ещё виден тот же признак (с адресами), затем цепочка «почему» до корня от 2-5 разных мест, ПРЕЖДЕ правки; остановка по признаку корня, не по числу звеньев; затем братья корня (вбок) и его зависимости (вниз); симптом чинится где заметили, причина — где возникла. Разбор гейт читает из текста хода и из тела вызова Bash `: <<'CHAIN'` … `CHAIN` (D484); в тексте отказа этот канал не назван намеренно. Отказ снимает названный исход (`scripts/outcome.sh`, сверенный с записью разбора, D1035) либо след разбора; чтения его не снимают (D1033); произнести цепочку текст отказа не требует (D513) |
| 🔔 Session ending | session-collector (Stop) | Self-assess, `/learn` пропущенное, `/save` |
| 🧠 Захват знаний | knowledge-capture-reminder (PostToolUse) | N коммитов за сессию, а с прошлого напоминания ТЫ в базу ничего не записал — собери материал в `_drafts/` или `/learn`, пока контекст свеж. Две области названы раздельно намеренно: маркер окна продвигается на каждом вызове хука, поэтому «нет записей» относится к промежутку между напоминаниями, а не ко всей сессии. С 12 сентября 2026 (D400) названа и третья область — ЧЬИХ записей нет: база знаний общая для всех сессий и проектов, и прежний признак (свежий файл в каталоге) гасил напоминание от чужой записи; теперь захват читается по действиям хода в расшифровке. Предел: без расшифровки захват не засчитывается, напоминание выйдет и на правильном поведении. Заполняет щель между retry-триггером (error-tracker) и Stop-триггером (session-collector): длинная успешная сессия проваливалась мимо обоих |
| 📝 CHANGELOG | changelog-reminder (PreToolUse, git commit) | Изменён код, но CHANGELOG.md не в staged — добавь запись (если содержательно). Scoped: только реальный код, не docs/tests/SESSION |
| ⚙️ AP1 trust-guard | trust-guard (PreToolUse, destructive Bash) | Без auth — переспроси прежде чем выполнять |
| ⚙️ AP2 distressed | intrusiveness-tracker | downgrade любой outcome до silent_prep/ignore, proactive запрещён |
| ⚙️ AP3 silence debt | session-start, session-collector | Учитывать в gate, не батч-вывод |
| 🔤 Output language | output-language-check (Stop/UserPromptSubmit/PreCompact/PreToolUse) | Чистить смешение алфавитов в следующих ответах |
| 📅 Относительное время без якоря | relative-date-check (Stop/UserPromptSubmit/PreCompact/PreToolUse) | Сверить время события с текущим, поставить абсолютный якорь рядом: «вчера (20 августа)», «час назад (в 19:40)» |
| ⚠️ completion-gate: закрытие расходится с критерием | completion-gate (Stop) | «Проверка» ☑-пункта красная — почини мир до зелёной команды либо верни метке ◐; красное ☑ архиватор не унесёт |
| ⚠️ completion-gate: «Проверка» ОТКРЫТОГО пункта не красная | completion-gate (Stop) | Зелёная у ☐/◐ значит одно из двух и оба дефект: пора закрывать с показанием либо команда не о дефекте. «Синтаксис» — строка не проверяет ничего. У открытого пункта второго рубежа нет: архиватор его не касается |
| ℹ️ completion-gate: ☑ ждёт финального скептика | completion-gate (Stop) | Пункт защитного слоя (путь в `hooks/`) готов по своей «Проверке»: запусти скептика opus по коммитам починки, затем ☑ со строкой «**Скептик.** opus, …» и строкой «**Происхождение.** H1 — <коммит> <путь>:<строка>; братьев N: \`<поиск>\`» на каждую находку H/M (или «— пунктом D<N>», «— не подтвердилась: <довод>»). Без них ☑ отбивает `backlog-open-write-guard` (D1137, D1305) |

`blocker: true` — явное решение, не автомат. Criteria: confirmed knowledge-action gap, measurable detection signals, `confirmed_count ≥ 5`, outcome:error. Schema в `knowledge/META.md`.

`/learn` (30s, во flow) vs `/retro` (2-5min, после significant events).

## Хук зовёт инструмент

**У прибора три состояния, а не два.** «Инструмента здесь нет» — молчать и выходить с 0: это не отказ, а другой проект; гейт `[ -f "$TOOL" ] || exit 0` стоит ДО вызова. «Инструмент сломался» (код ≥ 2 либо пустой вывод при живом файле) — говорить, потому что молчание тут читается как «чисто». «Отработал, находок нет» — молчать. Свалить первые два в один канал значит пустить два смысла по одному проводу — повод 7 сентября 2026, восемь пустых ходов подряд. Механическая часть — `hooks/tool-gate-check.sh` (PostToolUse на правку `hooks/*.sh`).

**Новый механизм начинается с вопроса «чем это решалось раньше».** Предмет почти никогда не
бывает нерешённым совсем: у него есть текстовое правило, чужой скрипт, запись в реестре либо
прибор, уже знающий ответ и просто не отдающий его наружу. Пропуск этого шага даёт одно из
трёх, и все три наблюдались: ВТОРАЯ реализация того же знания (у факта два владельца, они
расходятся молча — корень R1); старое правило ШУМИТ поверх нового механизма, веля делать то,
что тот делает сам; старое правило БЛОКИРУЕТ новый механизм — страж под прежнее устройство
отбивает вызовы нового, и это дороже всего: механизм есть, а работать не может.
Поиск занимает минуту (`git grep` по предмету в коде, по правилам в `rules/CLAUDE.md` и
`docs/`, `dep-index.py --impact` по задетым), и найденное получает ЯВНУЮ судьбу, записанную
рядом: предшественник снят · остаётся, и новый механизм ЗОВЁТ его · оба нужны, и названо, чем
предметы различаются. Умолчание тут неотличимо от «не посмотрел».
Повод — поправка владельца 10 сентября 2026, поймавшая это в тот же час: сверщику числа
корней писался свой счётчик, тогда как карту уже разбирал `scripts/root-map.py`; ему добавлен
режим `--count`, и владелец факта остался один. Полная процедура — `docs/development.md`,
§ «Новый механизм: сперва узнай, ЧЕМ вопрос решался раньше».

**Замер начинается с вопроса «кто уже это записал».** Прежде чем строить зонд, ставить свой хук
или запускать волну агентов ради ФАКТА — назови прибор, который этот факт уже пишет в мир, и
прочитай ответ у него. Система ведёт состояние (`hooks/state`), журналы, снимки и счётчики, а
вместе с ними ИМЕНА файлов и ключи дедупа: каждый такой след — уже сделанное наблюдение, и оно
дешевле нового на порядок. Повод измерен 17 сентября 2026 (D449): вопрос «какую расшифровку
получает хук при вызове из субагента» решался волной из трёх зондов (43 секунды, 279 тысяч
токенов) и двумя отбитыми попытками поставить свой хук, тогда как ответ лежал в
`state/subagent-cut-*.seen` с 10 сентября — ключ дедупа там равен `cksum` ПУТИ расшифровки, и
сверка его с кандидатами дала 16 из 16 «родитель» одной командой.
Порядок, а не вкус: (1) какой прибор уже пишет этот факт; (2) читается ли ответ из его следа
ОБРАТИМЫМ отображением — `cksum` пути, имя файла, счётчик, — а не догадкой по смыслу; (3) когда
след написан, потому что прежняя версия кода говорит о прошлом мире; (4) только теперь зонд — и
ровно на то, чего в следах нет.
НАЗВАННЫЙ ПРЕДЕЛ, без которого правило вредно: след отвечает ровно на то, что он записывал, и в
той единице, в какой записывал. Тот же ключ дедупа дал ПУТЬ и не мог дать СОСТАВ payload: поля
`agent_id` не читает ни один хук дерева (0 из 22 читателей `transcript_path`), своего следа у
него нет, и там зонд был единственной дорогой — он и дал `agent_id`, `agent_type`,
`agent_transcript_path`. Зонд ставится временно, в настройках ПРОЕКТА, и снимается в том же ходу.
Уровень 1 (текст) назван честно: у признака «ход строит зонд ради факта, который уже записан»
точность не измерена никем. Условие заведения стража: выборка ходов с замерами и доля тех, где
ответ лежал в следах.

Механическая половина правила заведена 21 сентября 2026: `hooks/own-frame-notice.sh`
(PreToolUse[Bash]) спрашивает про владельца факта, когда строится своя рамка замера —
heredoc со скриптом в scratchpad. Признак узок и измерен владельцем корпуса: 34 совпадения
на 40 582 вызова (0,08%). Подсказка, а не отказ: прибора может не быть вовсе, и тогда своя
рамка — единственная дорога. Дедуп судит ПРЕДМЕТ рамки, а не сессию, потому что в одном
ходу бывает несколько разборов. Повод: в день заведения правило нарушено трижды при живых
приборах, и запись знания закрыта исходом `applicable_not_followed`.

**Периодичность считается в единицах РАБОТЫ, а не календаря.** У механизма, который решает
«пора ли» — перемерять, гасить, чистить, пересчитывать, — предметом стоит «сколько
наработано», а не «сколько прошло»: за день дерево переписывают, за год тишины не меняется
ничто. Мера — дни ОПЫТА (`fsrs_experience_days_since` / `fsrs_experience_days_since_epoch`,
`hooks/fsrs-lib.sh`: уникальные сессии Session Registry, делённые на темп); календарь остаётся
ФОЛЛБЕКОМ там, где реестра нет. Для сроков мельче дня та же мера берётся ходами: хук границы
хода зовётся раз на ход, и его собственные вызовы и есть счётчик наработанного. У замера, чей
предмет двигают КОММИТЫ, а не сессии (набор в чистой рамке), единица — коммиты с последнего
прогона: период «Nc» в `scripts/measurements.tsv` (с 12 сентября 2026; повод — 569 коммитов
за 12 дней прошли «не просроченными» при периоде 30 дней, и первый push дал 12 красных). Календарь
законен ровно там, где он и есть предмет, и это пишется вслух с доводом — так сделано в
`disagreement-lib.sh:303-317` (контекст уходит по времени) и в prereg-сроке ablation
(`scripts/ablation/phase.sh:50`).
До 10 сентября 2026 то же правило стояло здесь ОДНОЙ строкой внутри «Knowledge evolution →
Decay (FSRS)», то есть в контексте старения знаний. Замер того дня: механизмов, решающих
«пора ли», шесть — календарём решали шесть, счётчик опыта звали ноль, при том что он лежал
в дереве с августа. Правило читали те, кто писал про знания; писавшие дроссель в хук туда
не заглядывали. Область правила была уже его предмета — оттого оно и не исполнялось.
Карта: корень R4 в `ROOTS.md`, проба `scripts/probes/R4.sh`.

**Единица берётся у того, кто назначает СРОК.** Правило выше — про срок, который механизм
назначает САМ. Если же срок задан соседом, единицу берут у соседа: точка и граница одного
окна на разных осях несравнимы. Повод измерен 11 сентября 2026 (D391): «залежалось»
перевели на дни опыта, а срок жизни той же записи задаёт `dis_expire_old`
(`hooks/disagreement-lib.sh:318`) и он календарный — осознанно, с доводом и замером
(сессия линейкой не годится: одна дала 156 событий Stop и шла сутки, другая закрылась за
минуту, разброс в 150 раз). При темпе того дня семь календарных дней равнялись трём дням
опыта, ровно порогу «залежалось», — окно схлопнулось в точку, и запись истекала в тот же
миг, когда её впервые можно было так назвать. Держали предмет верно ноги теста, а не
механизм. Перевод на опыт, сделанный без сверки с соседней границей, и был ошибкой.

**Адрес инструмента ClaudSoul берётся у ClaudSoul, а не у проекта сессии.** Из `scripts/` в мир доставляется один файл, остальные живут только в репозитории — ADR-018 (`docs/decisions.md`). Резолв идёт через `CLAUDSOUL_ROOT` (`hooks/paths-lib.sh:20,39-59`; цепочка: переменная → `CLAUDSOUL_REPO` → указатель `~/.claude/claudsoul-repo` → дефолт), как у `session-collector.sh:494`, `metrics-collector.sh:628`, `knowledge-audit-digest.sh:402`. Откат на корень чужого проекта — не запасной путь, а способ исполнить посторонний одноимённый файл: гейт `-f` своего от чужого не отличает, и замер это подтвердил — чужой прибор исполнялся, а его носители ложились в ОБЩИЙ снимок. Запасная ветка библиотеки объявляет ВСЕ имена, которые файл потом читает: под `set -u` недостающее имя убивает хук на первом же чтении, молча и до начала работы.

**На событии Stop постоянное состояние в `additionalContext` печатать запрещено.** Непустой `additionalContext` на Stop перезапускает ход, поэтому состояние, которое не меняется само (нет файла, нет ключа, сломанная конфигурация), напечатается на КАЖДОМ ходу и даст цикл: замер трёх подряд ходов со сломанным прибором дал 3 перезапуска из 3. Разовое, самоустраняющееся событие печатать можно. Для постоянного — три устройства, все три уже стоят в дереве: тормоз `stop_hook_active` (`timestamp-canary-check.sh:48`), «копить на Stop — говорить на следующем ходу» (`output-language-check.sh:160-167`), очередь `pending-alerts.txt` **в паре с дросселем** по составу состояния (`hooks/throttle-lib.sh`; образцы — `carrier-growth-check.sh:106-119`, `install-drift-notice.sh:62-68`). Пара названа целиком не для полноты: очередь снимает ПЕРЕЗАПУСК хода, но не ПОВТОР содержимого — каждую дописанную строку она доставляет ровно раз, а дописать ту же строку на следующем Stop не мешает. До 8 сентября 2026 здесь стояла одна очередь, и третий её потребитель следовал правилу как написано: `session-collector.sh` дросселя не имел, и свод нёс 69-94% пользовательских ходов в четырёх сессиях (52/64, 46/67, 41/48, 31/33) при неизменных 162 631 байте на прогон. Ключ дросселя — СОСТАВ состояния, а не его тело: «открытых стало 146 вместо 145» звучать не должно, «появились залежавшиеся» — обязано. Голый `systemMessage` в VSCode-расширении не рендерится, но молчанием НЕ является: в мобильном клиенте он рендерится построчно — см. § «Назови поверхность», поправка 12 сентября 2026. Само свойство события Stop принято по свидетельствам внутри системы; прямого замера нет — D349.

**Хук Stop, который ничего не решает за ход, регистрируется фоновым.** Владелец получает ход назад, только когда кончится САМЫЙ ДОЛГИЙ синхронный хук Stop: все они идут параллельно, и цена границы — максимум, а не сумма. Повод — D1000 (17 октября 2026): владелец ждал после каждого ответа 4–10 минут, замер 508 границ дал у `session-collector.sh` медиану 100 с. Поэтому хук, который говорит только через очередь `pending-alerts.txt` (её показывают на следующей реплике), ставится в регистрации `install.sh` с `"async": true` — так стоят `session-collector.sh`, `completion-gate.sh`, `declared-problem-recorded.sh` и `carrier-growth-check.sh` (два последних — с 7 ноября 2026, D1235: первый говорит только файлом напоминаний, второй держал ответ холодным прогоном реестра родов до 52 с). Фон годится не всем: фоновому хуку `decision` и `continue` не действуют, а его `additionalContext` придёт следующим ходом, — значит хук, чей вывод обязан перезапустить ход (канарейка, принятие варианта), остаётся синхронным и обязан быть дешёвым. Фоновый писатель общего файла сверяет файл перед записью: агент следующего хода правит тот же файл, пока фон держит прочитанную копию, а инструмент Edit замка не берёт (`scripts/backlog-refresh-readings.sh`, `scripts/backlog-archive.sh`). Фон не лечит цену, а прячет её: квадратичный перебор в фоне по-прежнему жжёт процессор и тормозит соседние хуки — замер того же дня показал, что p90 `declared-problem-recorded` вырастал с 2 до 23 с только на границах, где сборщик шёл дольше 120 с.
