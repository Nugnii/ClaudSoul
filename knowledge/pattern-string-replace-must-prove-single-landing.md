# Строковая замена обязана доказать, что легла ровно в одно задуманное место

**Правило.** Перед заменой по образцу — `assert s.count(образец) == 1` (или встроенная правка, которая сама отказывает на
неуникальном образце). Не `образец in s`: эта проверка отличает «нет» от «есть», но не «одно» от «несколько». Мутатор
теста вдобавок сверяет файл до и после и отказывает в вердикте при нулевом различии.

**Две формы одного промаха.**
- **Ноль вхождений** — правка молча не внесена. 2026-08-23: якорь awk-программы набран по виду, в файле кавычка
  записана через слой экранирования — три замены подряд не нашли строку. 2026-09-14: мутант искал строку с обратной
  кавычкой, в файле она экранирована — файл не изменён, тест «честно» зелёный, нога записана в вакуумные (из 13 мутирующих
  тестов дерева применение доказывали 4).
- **Больше одного** — правка легла не туда. 2026-09-07: якорь вставки по имени функции, первое вхождение — перечень в
  шапке; строка разорвалась, описание стало исполняемой командой. 2026-10-10 (ProjectA, B272): два одинаковых блока
  `onError` на странице «Счета», помощник `rep()` с `assert o in s` + `replace(o, n, 1)` поставил перевод в обработчик
  «Сверки с бухгалтерией»; тест роута был зелёным, дефект ушёл на прод.

**Почему не видно.** `str.replace`, `sed`, `awk` и самописные помощники дают одинаковый код 0 и запись файла при всех трёх
исходах. Вердикт по коду возврата снимается с одного провода при трёх состояниях мира.

**Дробь (2026-10-10, одна сессия).** Форма «проверка наличия + первое вхождение»: 16 команд, 44 замены (холостой прогон по
расшифровке), не туда — 1; форма `count(...) == 1` — 10 команд, промахов 0. Знание `case-2026-08-23-…` было в базе
всё время — жило привычкой, а не отказом.

**How to apply.** Любая правка заменой по образцу: python-heredoc, sed, awk, мутаторы тестов. Особенно там, где одинаковые
блоки — норма: обработчики `onError`/`onSuccess` нескольких мутаций в одном компоненте, повторяющиеся JSX-блоки,
однотипные ветки `case`, перечни в шапках файлов.

**Limitations.** Замена ВСЕХ вхождений (переименование) — законный другой случай: там утверждается ожидаемое число
вхождений, а не единица.

**Механизм.** Уровень 4 (отказ) стоит с 11 октября 2026: `hooks/replace-uniqueness-guard.sh` (ClaudSoul, D522) отбивает
вызов Bash, где программа питона в heredoc делает `.replace(a, b, 1)` без `count(`; в причине — форма `assert s.count(o) == 1`.
Замер до включения: из 3438 команд с заменой первого вхождения признак горел на 1619 (47%); выборка 14 из 14 — настоящие.
Не покрыты: `python3 -c`, sed/awk/perl и мутаторы тестов, пишущие файл не из heredoc, — там правило по-прежнему держится
этим знанием.
