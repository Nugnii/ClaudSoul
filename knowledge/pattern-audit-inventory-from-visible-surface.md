Перечень аудита строится по двум осям, и обе берутся из ПОРОЖДАЮЩЕГО источника, а не из видимой поверхности:
объекты — из кода (маршруты `page.tsx`, места окон, компоненты вложенных состояний: вкладки, аккордеоны, раскрывающиеся
строки, шаги, выдвижные панели, меню, подтверждения, наведение); правила — из полного текста норм, у каждого критерия
вместе со всем списком исключений. Меню, замечания владельца и ложные находки обхода проверяют охват, но не задают его.
Отчёт называет «N из M» по каждому виду объектов и перечень того, что не мерилось.

**Why:** три поправки владельца за три дня в ProjectA_NEW. 14 ноября: «Ты писал, что сделаешь аудит всех интерфейсов и
нихрена» — обход взял экраны из меню (37 из 56 страниц, 0 из 100 мест окон) и мерил одно свойство. Тот же день, после
переделки: «аудит не полный. нет проверки вкладок и аккордеонов… мои замечания, но никак не UX/UI нормы» — правила свели
из замечаний, вложенных состояний открыто 0 из 54. 16 ноября: «Вероятно стоит проверить везде где есть изменения при
наведении» — снова класс, а не место. Исключения критерия 2.5.8 брались по одному на ложную находку (6733, затем 264
находки) — два круга обхода по часу, хотя у критерия пять исключений, читаемых списком.

**How to apply:** до первого обхода — две команды-знаменателя (поиск по коду для объектов, оглавление нормы для правил)
и таблица «вид → M»; обещание «все» без M не давать.

**Limitations:** аудит одного экрана по одному замечанию — не этот случай. Норма без списка исключений (внутренний гайд) —
исключения брать из гайда, а не выдумывать.
